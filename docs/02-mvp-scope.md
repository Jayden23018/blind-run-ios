# 02 — MVP 范围文档

## 范围理念

本次 MVP 的核心约束是 **3 天内完成可演示版本**。所有范围决策遵循以下原则：

1. **演示闭环优先**：只要某个功能不直接支撑从预约到完成的完整 demo 流程，就排除在 MVP 之外。
2. **Mock 可接受**：对于 demo 而言，假数据、简化流程、占位页面都是可接受的。
3. **无障碍不可妥协**：VoiceOver、TTS、极简大按钮必须在每一个盲人端页面上正常工作。
4. **一个手机号可拥有双角色**：用户可以在 App 内切换 activeRole，但有活跃订单时禁止切换。

## 在范围内 (In-Scope)

### 通用模块（双角色共享）

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 手机号 + 验证码登录 | P0 | 验证码固定 `000000`，首次登录自动创建账号 |
| JWT Token 管理 | P0 | 登录返回 JWT，存储于 UserDefaults |
| 角色选择与切换 | P0 | 支持在盲人跑者 / 志愿者之间切换 |
| 角色切换拦截 | P0 | 存在 PENDING_ACCEPT / DRIVER_EN_ROUTE / DRIVER_ARRIVED / IN_PROGRESS 状态订单时禁止切换 |
| API 环境切换 | P1 | Debug 开发包支持 Mock / Demo Cloud；Demo/Production 包隐藏切换入口 |
| 设置页 | P2 | 基本设置：个人信息、关于、退出登录 |

### 盲人跑者端

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 盲人资料填写 | P0 | 必填：昵称、紧急联系人姓名、紧急联系人电话；选填：跑步经验 |
| 盲人首页 | P0 | 无订单时显示"开始约跑"大按钮 + 地图定位；有订单时显示订单状态卡片 |
| 创建预约 | P0 | 必填：出发地点、预约时间；选填：目的地/路线、预计时长、预计距离、配速偏好、是否需要同性志愿者、备注 |
| 订单状态等待页 | P0 | WebSocket 接收状态变化，断开时每 5 秒轮询订单详情 |
| 盲人服务中页面 | P0 | 显示志愿者信息，一键求助按钮，服务进行状态 |
| 盲人完成/评分页 | P0 | 显示完成状态，星级评分 UI（不强制提交） |
| 取消订单 | P0 | PENDING_MATCH / PENDING_ACCEPT / IN_PROGRESS 可取消，需二次确认 |
| 重复当前状态播报按钮 | P0 | 每个关键页面提供，与 VoiceOver 并存不冲突 |

### 志愿者端

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 志愿者资料 + Mock 认证 | P1 | 填写昵称，完成 Mock 认证页面后自动 approved |
| 志愿者首页 | P0 | 附近可接订单、可服务开关、积分信息 |
| 订单列表页 | P0 | 按距离排序的订单列表，下拉刷新 |
| 订单详情页 | P0 | 订单完整信息，「接单」按钮 |
| 志愿者服务中页面 | P0 | 「我已到达」按钮，「开始服务」流程，「结束服务」按钮 |
| 服务记录页 | P1 | 已完成的订单列表，显示时间、盲人昵称、积分 |
| 积分/商城占位页 | P2 | 积分余额展示 + "积分商城即将上线"占位文字 + 几个假商品 |
| 一键求助 | P0 | DRIVER_EN_ROUTE / DRIVER_ARRIVED / IN_PROGRESS 状态可触发，需二次确认；仅记录独立事件 |
| 取消订单 | P0 | 服务开始前可取消，需二次确认，记录 cancelledBy |

### 地图与定位

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 高德地图显示 | P0 | 展示地图、当前位置、订单地点 marker |
| 当前定位获取 | P0 | 使用 AMapLocation SDK |
| 禁定位拦截 | P0 | 拒绝定位权限时，盲人不能创建预约；志愿者可浏览但不显示距离，且不能接单 |
| 距离计算 | P0 | iOS 端根据志愿者位置和订单坐标计算距离 |
| 定位权限提示 | P0 | 引导用户开启定位权限 |
| 默认测试坐标 | P1 | 模拟器定位失败时提供默认测试坐标 |

### 语音与无障碍

| 功能 | 优先级 | 说明 |
|------|--------|------|
| VoiceOver 支持 | P0 | 所有盲人端关键按钮、输入框、状态文本配置 accessibilityLabel / accessibilityHint |
| TTS 语音播报 | P0 | AVSpeechSynthesizer，所有关键流程节点播报 |
| 语音输入 | P1 | Speech Framework，用于地点描述、备注等文本输入 |
| 极简大按钮 | P0 | 盲人端关键主按钮最小高度 64pt |
| 危险操作二次确认 | P0 | 取消订单、进入求助、结束服务、退出登录 |

### 外部云端 API 对接

| 模块 | 优先级 | 说明 |
|------|--------|------|
| auth（登录认证） | P0 | 手机号 + 验证码登录，返回 JWT |
| user（用户管理） | P0 | 用户创建、角色管理 |
| profile（资料管理） | P0 | 盲人/志愿者资料 CRUD |
| order（订单管理） | P0 | 订单 CRUD、状态流转、WebSocket 通知与轮询降级查询 |
| location（位置） | P1 | 位置信息存储 |
| safety（安全） | P0 | 紧急求助触发、紧急联系人存储 |
| volunteer（志愿者） | P0 | 认证状态管理、可服务开关 |
| OpenAPI 契约 | P0 | 以 `docs/07-api-contract.openapi.yaml` 驱动前端对接 |
| 并发接单错误处理 | P0 | 前端正确处理 `ORDER_ALREADY_ACCEPTED` |

以上均为 iOS 消费的外部服务能力。本仓库不实现或部署这些服务端模块。

## 在范围外 (Out-of-Scope)

| 排除功能 | 排除原因 |
|----------|----------|
| Android 客户端 | 只做 iOS |
| 完整管理员后台 | 独立范围，非 MVP 必需 |
| 真实短信服务 | 3 天约束，需第三方服务商接入 |
| 真实实名认证 | 需政府 API 集成 |
| 真实管理员审核后台 | 管理员角色不在 MVP 范围 |
| 实时轨迹共享 | 仅做当前定位与 WebSocket 位置上报，不做完整轨迹回放或路线共享 |
| 自动拨打电话 / 发送短信 | MVP 仅存储紧急联系人，不做真实通知 |
| AI 助手 / 复杂自然语言时间解析 | 超出 3 天范围 |
| 路线导航 | 不做复杂地图自动规划路线，由双方线下沟通 |
| 完整积分商城 | 仅占位展示，不做真实兑换、库存、支付 |
| App 内聊天 / 虚拟号码 | 接单后直接展示真实电话 |
| 复杂风控 / 摔倒检测 / 电子围栏 | 超出 MVP 范围 |
| 即时呼叫 | 只做提前预约 |
| 多人活动报名 | 只做一对一服务 |
| 头像上传 | 不做 |
| 多语言 / 国际化 | 仅中文 |
| iPad 专属版本 | 可用来演示，但不单独适配 |
| 离线模式 | 需网络连接 |
| 系统级推送通知 | MVP 使用 App 内 WebSocket 通知，不接 APNs 推送 |

## 技术栈决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| UI 框架 | SwiftUI | 开发速度快，MVVM 天然适配 |
| 架构 | MVVM | 简单性与可测试性平衡，适合 3 天构建 |
| 地图 | 高德地图 iOS SDK | 需求指定，非 Apple MapKit |
| 网络层 | URLSession + async/await | 原生，无额外依赖 |
| Token 存储 | UserDefaults | MVP 简化，正式版迁移 Keychain |
| 实时更新 | WebSocket + 5 秒轮询降级 | 云端契约要求 WebSocket，轮询用于断线兜底 |
| 外部 API | `http://47.114.113.171` | 唯一真实联调服务，不由本仓库维护 |
| 认证 | JWT | 无状态，移动端友好 |

## 环境配置

### 两种 API 模式

| 模式 | 说明 | 使用场景 |
|------|------|----------|
| Mock | 本地假数据，无后端 | UI 和流程调试 |
| Demo Cloud | `http://47.114.113.171` | 所有真实网络联调；Demo/Production 包固定使用 |

### 高德地图 Key 管理

- Key 存储在 `LocalConfig.xcconfig` 或本地 plist 中。
- 本地配置文件加入 `.gitignore`，不提交 Git。
- 项目提供 `LocalConfig.example.xcconfig` 说明需要哪些 key。

## Demo 演示脚本

### 场景 1：完整正向流程（Happy Path）

| 步骤 | 操作 | 设备 | 预期结果 |
|------|------|------|----------|
| 1 | 盲人登录（手机号 + 000000） | 手机 A | 进入角色选择页 |
| 2 | 盲人选择"盲人跑者"角色 | 手机 A | 进入盲人资料页（首次） |
| 3 | 盲人填写资料并提交 | 手机 A | 进入盲人首页 |
| 4 | 盲人点击"开始约跑" | 手机 A | 进入创建预约页 |
| 5 | 盲人选择出发地点、预约时间，提交 | 手机 A | 进入订单等待页，TTS 播报"订单已提交" |
| 6 | 志愿者登录 | 手机 B | 进入角色选择页 |
| 7 | 志愿者选择"志愿者"角色 | 手机 B | 进入志愿者认证页（首次） |
| 8 | 志愿者完成 Mock 认证 | 手机 B | 进入志愿者首页，看到订单 |
| 9 | 志愿者点击订单，查看详情 | 手机 B | 显示订单详情 |
| 10 | 志愿者点击"接单" | 手机 B | 订单状态变为 PENDING_ACCEPT |
| 11 | 盲人端轮询到状态变更 | 手机 A | 页面更新，TTS 播报"志愿者已接单" |
| 12 | 志愿者点击"我已出发" | 手机 B | 订单状态变为 DRIVER_EN_ROUTE |
| 13 | 志愿者点击"我已到达"并开始服务 | 手机 B | 订单状态依次进入 DRIVER_ARRIVED、IN_PROGRESS；盲人端播报到达和开始 |
| 14 | 志愿者点击"结束服务" | 手机 B | 订单状态变为 COMPLETED |
| 16 | 盲人端轮询到状态变更 | 手机 A | 显示完成页面 + 评分 UI，TTS 播报"服务已完成" |
| 17 | 盲人评分（可选） | 手机 A | 完成评分，返回首页 |

### 场景 2：紧急求助流程

| 步骤 | 操作 | 设备 | 预期结果 |
|------|------|------|----------|
| 1 | 订单处于 IN_PROGRESS 状态 | 双设备 | — |
| 2 | 志愿者点击"紧急求助" | 手机 B | 弹出确认弹窗 |
| 3 | 志愿者确认求助 | 手机 B | emergency event 被记录，订单状态保持原生命周期状态 |
| 4 | 盲人端轮询到状态变更 | 手机 A | 显示紧急求助页面，TTS 播报"进入求助状态" |

### 场景 3：角色切换拦截

| 步骤 | 操作 | 设备 | 预期结果 |
|------|------|------|----------|
| 1 | 志愿者接单后（PENDING_ACCEPT 状态） | 手机 B | — |
| 2 | 志愿者尝试切换角色 | 手机 B | 弹窗提示"您有进行中的订单，无法切换角色" |
| 3 | 确认提示 | 手机 B | 保持在当前角色页面 |

## 3 天构建计划

| 天数 | 重点 | 产出 |
|------|------|------|
| **Day 1** | 项目搭建 + 认证 + 导航壳 | Xcode 模块结构、高德 SDK、手机号登录、角色选择、Tab 导航、APIClient 与云端认证对接 |

| **Day 3** | 无障碍 + 联调 + 打磨 | VoiceOver、TTS、语音输入、紧急求助、错误处理、前端测试和双设备 Demo 走查 |

## 已知限制（Demo 声明）

1. 验证码固定为 `000000`，未接入真实短信服务。
2. 志愿者认证为 Mock 数据，非真实实名审核。
3. GPS 使用设备当前位置，不展示另一方实时位置。
4. 积分仅展示，不走真实兑换。
5. 云端服务由外部团队维护；可用性和数据生命周期不由本仓库控制。
6. 定位依赖设备 GPS / 模拟器模拟定位，室内可能信号不佳。
7. 仅支持 iOS 16+，不支持 Android。
