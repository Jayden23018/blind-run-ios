# 02 — MVP 范围文档

## 范围理念

本次 MVP 的核心约束是 **3 天内完成可演示版本**。所有范围决策遵循以下原则：

1. **演示闭环优先**：只要某个功能不直接支撑从预约到完成的完整 demo 流程，就排除在 MVP 之外。
2. **Mock 可接受**：对于 demo 而言，假数据、简化流程、占位页面都是可接受的。
3. **无障碍不可妥协**：VoiceOver、TTS、极简大按钮必须在每一个盲人端页面上正常工作。
4. **一个手机号可拥有双角色**：用户可以在 App 内切换 activeRole，但有活跃订单时禁止切换。

## 在范围内 (In-Scope)

### 通用模块（双角色共享）

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 手机号 + 验证码登录 | P0 | 验证码固定 `123456`，首次登录自动创建账号 |
| JWT Token 管理 | P0 | 登录返回 JWT，存储于 UserDefaults |
| 角色选择与切换 | P0 | 支持在盲人跑者 / 志愿者之间切换 |
| 角色切换拦截 | P0 | 存在 accepted / arrived / in_progress / emergency 状态订单时禁止切换 |
| API 环境切换 | P1 | Mock / Local Backend / Production Backend 三种模式 |
| 设置页 | P2 | 基本设置：个人信息、关于、退出登录 |

### 盲人跑者端

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 盲人资料填写 | P0 | 必填：昵称、紧急联系人姓名、紧急联系人电话；选填：跑步经验 |
| 盲人首页 | P0 | 无订单时显示"开始约跑"大按钮 + 地图定位；有订单时显示订单状态卡片 |
| 创建预约 | P0 | 必填：出发地点、预约时间；选填：目的地/路线、预计时长、预计距离、配速偏好、是否需要同性志愿者、备注 |
| 订单状态等待页 | P0 | 每 5 秒轮询订单详情，展示匹配状态变化 |
| 盲人服务中页面 | P0 | 显示志愿者信息，一键求助按钮，服务进行状态 |
| 盲人完成/评分页 | P0 | 显示完成状态，星级评分 UI（不强制提交） |
| 取消订单 | P0 | 仅匹配中状态可取消，需二次确认 |
| 重复当前状态播报按钮 | P0 | 每个关键页面提供，与 VoiceOver 并存不冲突 |

### 志愿者端

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 志愿者资料 + Mock 认证 | P1 | 填写昵称，完成 Mock 认证页面后自动 approved |
| 志愿者首页 | P0 | 附近可接订单、可服务开关、积分信息 |
| 订单列表页 | P0 | 按距离排序的订单列表，下拉刷新 |
| 订单详情页 | P0 | 订单完整信息，「接单」按钮 |
| 志愿者服务中页面 | P0 | 「我已到达」按钮，「开始服务」流程，「结束服务」按钮 |
| 服务记录页 | P1 | 已完成的订单列表，显示时间、盲人昵称、积分 |
| 积分/商城占位页 | P2 | 积分余额展示 + "积分商城即将上线"占位文字 + 几个假商品 |
| 一键求助 | P0 | accepted / arrived / in_progress 状态可触发，需二次确认 |

### 地图与定位

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 高德地图显示 | P0 | 展示地图、当前位置、订单地点 marker |
| 当前定位获取 | P0 | 使用 AMapLocation SDK |
| 禁定位拦截 | P0 | 拒绝定位权限时，盲人不能创建预约，志愿者不能查看/接单 |
| 距离计算 | P0 | iOS 端根据志愿者位置和订单坐标计算距离 |

| 默认测试坐标 | P1 | 模拟器定位失败时提供默认测试坐标 |

### 语音与无障碍

| 功能 | 优先级 | 说明 |
|------|--------|------|
| VoiceOver 支持 | P0 | 所有盲人端关键按钮、输入框、状态文本配置 accessibilityLabel / accessibilityHint |
| TTS 语音播报 | P0 | AVSpeechSynthesizer，所有关键流程节点播报 |
| 语音输入 | P1 | Speech Framework，用于地点描述、备注等文本输入 |
| 极简大按钮 | P0 | 盲人端关键主按钮最小高度 64pt |
| 危险操作二次确认 | P0 | 取消订单、进入求助、结束服务、退出登录 |

| 模块 | 优先级 | 说明 |

| profile（资料管理） | P0 | 盲人/志愿者资料 CRUD |

| Seed 测试数据 | P0 | 启动时自动插入测试数据 |

## 在范围外 (Out-of-Scope)

| 排除功能 | 排除原因 |
|----------|----------|
| Android 客户端 | 只做 iOS |
| 完整管理员后台 | 独立范围，非 MVP 必需 |
| 真实短信服务 | 3 天约束，需第三方服务商接入 |
| 真实实名认证 | 需政府 API 集成 |
| 真实管理员审核后台 | 管理员角色不在 MVP 范围 |
| WebSocket | 后端复杂度高，轮询对 demo 足够 |
| 实时轨迹共享 | 高德轨迹 SDK 复杂，5 秒轮询定位已足够 |
| 自动拨打电话 / 发送短信 | MVP 仅存储紧急联系人，不做真实通知 |
| AI 助手 / 复杂自然语言时间解析 | 超出 3 天范围 |
| 路线导航 | 不做复杂地图自动规划路线，由双方线下沟通 |
| 完整积分商城 | 仅占位展示，不做真实兑换、库存、支付 |
| App 内聊天 / 虚拟号码 | 接单后直接展示真实电话 |
| 复杂风控 / 摔倒检测 / 电子围栏 | 超出 MVP 范围 |
| 即时呼叫 | 只做提前预约 |
| 多人活动报名 | 只做一对一服务 |
| 头像上传 | 不做 |
| 多语言 / 国际化 | 仅中文 |
| iPad 专属版本 | 可用来演示，但不单独适配 |
| 离线模式 | 需网络连接 |
| 推送通知 | 用轮询替代 |

## 技术栈决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| UI 框架 | SwiftUI | 开发速度快，MVVM 天然适配 |
| 架构 | MVVM | 简单性与可测试性平衡，适合 3 天构建 |
| 地图 | 高德地图 iOS SDK | 需求指定，非 Apple MapKit |
| 网络层 | URLSession + async/await | 原生，无额外依赖 |
| Token 存储 | UserDefaults | MVP 简化，正式版迁移 Keychain |
| 实时更新 | 5 秒轮询 | 比 WebSocket 简单，demo 足够 |
| 后端框架 | Spring Boot | 行业标准，快速开发 |
| Demo 数据库 | H2 | 零配置，适合 demo |
| 认证 | JWT | 无状态，移动端友好 |
| 后端 ORM | Spring Data JPA | 标准方案 |

## 环境配置

### 三种 API 模式

| 模式 | 说明 | 使用场景 |
|------|------|----------|
| Mock | 本地假数据，无后端 | UI 和流程调试 |
| Local Backend | 局域网连接 Spring Boot | Mac 运行后端，iPhone/iPad 局域网访问 |
| Production Backend | 公网后端 | 后续扩展 |

### 高德地图 Key 管理

- Key 存储在 `LocalConfig.xcconfig` 或本地 plist 中。
- 本地配置文件加入 `.gitignore`，不提交 Git。
- 项目提供 `LocalConfig.example.xcconfig` 说明需要哪些 key。

## 3 天构建计划

| 天数 | 重点 | 产出 |
|------|------|------|
| **Day 1** | 项目搭建 + 认证 + 导航壳 | Xcode 项目结构（Core/Auth/Role/BlindRunner/Volunteer/Orders/Map/Voice/Safety/Profile 模块）、高德 SDK 集成、手机号登录页、角色选择页、Tab 导航骨架、Spring Boot 项目搭建、auth + user + profile API、Swagger 文档 |
| **Day 2** | 核心业务流程 | 盲人端全部 5 页、志愿者端全部 7 页、订单状态机、轮询引擎、地图 + 定位集成、后端 order + location + volunteer API |
| **Day 3** | 无障碍 + 联调 + 打磨 | VoiceOver 全覆盖、TTS 全部节点播报、语音输入集成、紧急求助完整流程、并发接单保护、订单状态流转完整测试、无障碍专项测试、Demo 走查 |

## 已知限制（Demo 声明）

1. 验证码固定为 `123456`，未接入真实短信服务。
2. 志愿者认证为 Mock 数据，非真实实名审核。
3. GPS 使用设备当前位置，不展示另一方实时位置。
4. 积分仅展示，不走真实兑换。
5. 后端使用 H2 内存数据库（每次重启数据重置，seed 测试数据除外）。
6. 定位依赖设备 GPS / 模拟器模拟定位，室内可能信号不佳。
7. 仅支持 iOS 16+，不支持 Android。
