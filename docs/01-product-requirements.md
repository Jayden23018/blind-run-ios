# 01 — 产品需求文档 (PRD)

## 产品名称

**助盲跑 (AidRun)** — 连接盲人跑者与志愿者的户外跑步协助服务平台。

## 产品定位

助盲跑是一款面向盲人跑者与志愿者的双角色移动产品，目标是在户外跑步场景中建立安全、可预约、可追踪的协助服务闭环。

当前上线版聚焦**预约型服务**，以真实地图、真实定位、真实后端订单闭环和无障碍体验为发布基础。产品形态为 iOS App，按角色进入不同流程：

- **盲人端**：强调极简触控、低认知负担、关键节点语音播报。
- **志愿者端**：强调接单与服务执行闭环。
- **平台侧**：优先保障订单闭环与安全可追踪性。

## 项目背景

- **项目类型**：公益助盲跑服务产品。
- **目标用户**：可面向真实盲人跑者、志愿者和公益组织试点使用。
- **第一版目标**：完成可上线试点的 iOS 客户端，真实接入高德地图和外部后端，并明确记录尚未完成的生产风险。

## 目标用户与角色画像

### 角色 A：盲人跑者

| 维度 | 描述 |
|------|------|
| 核心需求 | 安全地完成户外跑步，获得志愿者协助 |
| 痛点 | 导航障碍、障碍物规避、安全隐患 |
| 典型场景 | 提前预约志愿者，在约定时间地点会合，共同完成跑步 |
| 技术依赖 | 高度依赖语音交互（VoiceOver + TTS），触控操作为辅助 |

### 角色 B：志愿者

| 维度 | 描述 |
|------|------|
| 核心需求 | 通过结构化渠道提供帮助，获得积分奖励 |
| 痛点 | 缺乏与盲人跑者对接的便捷渠道 |
| 典型场景 | 开启上线接单后等待系统派单，在 30 秒内接受或拒绝派单；接单后查看出发点位置并前往会合，全程陪伴跑步 |
| 激励 | 每完成一次服务获得 +100 积分；当前 iOS 先展示积分，兑换能力按路线图接入 |

### 暂不作为独立角色

- 管理员
- 紧急联系人
- 机构 / 公益组织

> 注：后端保留管理员审核相关字段，为后续扩展做准备。

## 核心价值主张

- **对盲人跑者**：可预约的陪伴式跑步协助，极简无障碍交互；紧急求助入口当前 release 隐藏，后续安全专项启用。
- **对志愿者**：有意义的公益参与，积分激励体系，灵活的时间安排。

## 第一版发布标准

1. 能完整演示：**盲人预约 → 志愿者接单 → 志愿者出发 → 志愿者到达并开始服务 → 志愿者结束服务 → 盲人看到完成状态**。
2. 必须接入真实地图（高德地图）。
3. 必须接入真实定位。
4. 必须接入真实用户登录。
5. 必须体现无障碍体验，包括 VoiceOver、TTS、极简大按钮。
6. 必须在真机 `111` 和 `iPad Pro (2)` 上通过真实高德 smoke、真实云端 UI smoke 和后端 E2E。
7. 固定验证码和 HTTP 明文 IP 已确认可用于当前上线版本；UserDefaults token 仍需在 `plan.md` 中记录为后续硬化项。

## 关键技术约束

| 约束项 | 决策 |
|--------|------|
| 客户端 | Swift 原生 iOS，SwiftUI + MVVM |
| iOS 版本 | iOS 16+ |
| 外部服务 | 仓库外云端 API，唯一地址 `http://47.114.113.171` |
| 网络层 | URLSession + async/await |
| Token 存储 | 当前用 UserDefaults；上线前优先迁移 Keychain，未迁移需记录风险 |
| 地图服务 | 高德地图（AMap） |
| 实时通信 | REST + WebSocket；志愿者通过 WebSocket 接收系统派单，订单页保留每 5 秒轮询作为 WebSocket 断开时的降级方案 |
| 短信验证 | `send-code` / `verify-code` 后端验证码策略；预置测试账号固定 `000000` |
| 志愿者认证 | 身份证、人脸核验、管理员审核按后端 OpenAPI 契约接入 |
| 环境切换 | Debug 支持 Mock / Demo Cloud；Demo 和 Production 构建固定 Demo Cloud |
| 主题 | 支持系统深色 / 浅色模式，优先保证可读性和对比度 |

## 账户生命周期与会话安全

- 启动时必须先通过 `GET /api/auth/me` 验证已存 JWT；无角色或 `UNSET` 的有效会话进入角色选择且不连接角色 WebSocket。
- 正常退出必须先调用 `POST /api/auth/logout`。网络或服务端失败时保留会话，并提供重试或经再次确认的“仅退出本机”。
- 两种角色均可自助软删除自己的账户；删除需两阶段确认，存在活动订单时禁止删除，服务端成功后才清理本地数据。
- HTTP 429 必须使用服务端重试秒数；认证类倒计时不得冻结无关功能。

## 全局实时事件体验

- 登录且角色有效时，实时事件由 `AppState` 持有的单一 app-lifetime 协调器接收，不能依赖首页、订单页或服务页是否挂载。
- 关联当前订单且状态合法的 `ORDER_STATUS_CHANGED` 立即推进双端本地状态，并使用客户端固定无障碍文案播报一次；`messageId` 用于当前登录会话内的重连去重，身份碰撞不得采用消息内容。REST 详情刷新与盲人端五秒轮询继续补充完整字段并兜底断线、漏事件和合同异常，迟到结果不得回退已接受状态。
- 与结构化状态事件并行到达的生命周期 `APP_NOTIFICATION` 不得重复播报；活动订单卸载后的短时终态通知也按状态语义抑制。安全告警和非生命周期通知保持原有呈现。
- 志愿者 `NEW_ORDER` 在页面导航期间仍保留原有后端倒计时与接受/拒绝操作，不增加公开订单池或“稍后处理”。
- 前台 `HIGH` 通知抢占 `NORMAL`，可见文案、VoiceOver 标签和 TTS 含义一致；普通重复消息受限去重，不得合并不同事件 ID 的安全提醒。
- 双向 peer location 在 `DRIVER_EN_ROUTE`、`DRIVER_ARRIVED`、`IN_PROGRESS` 展示给当前订单双方；`IN_PROGRESS` 支持锁屏/后台连续定位。分离/信号告警只按后端通知展示，不改变订单或触发 iOS SOS。
- 盲人端 eligible pre-service 阶段在 socket 位置缺失或过期时，可使用 `/api/blind/volunteer-location` 30 秒新鲜度回退；五秒订单详情轮询始终保留。

## 实时同行与完成轨迹

- 设备原生定位为 WGS-84，iOS 在唯一网络边界转换为 GCJ-02；服务端返回坐标直接按 GCJ-02 使用。
- 当前订单双方每 5 秒上报真实位置，同行位置超过 15 秒即隐藏；云端不得接收 Mock/Demo 坐标。
- 服务完成后以盲人轨迹作为“本次路线”，展示可用的里程、时长和平均配速，并提供独立于地图的文本、VoiceOver、TTS 与重复状态摘要。
- 志愿者轨迹只为未来经批准的异常评估保留；当前 100 米/连续 2 次工程阈值不产生完成轨迹异常结论。
