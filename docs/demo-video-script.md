## 1. 分镜表

| 时间 | 画面 | 声音 | 字幕（逐字） |
|---|---|---|---|
| **0–8s** | 实拍。清晨跑道边，视障跑者独自站着，手里白手杖。中景 → 缓推近。**不要拍脸部特写博同情** | 只有环境音（鸟叫、远处车流）。**无旁白** | 想去跑步，但一个人不敢出门。 |
| **8–18s** | 实拍手持机位起，摇到手机屏幕；随后**切纯录屏**。屏幕上语音波形起伏 | 跑者真实语音：「明天早上八点，去奥体中心跑步，跑一个小时」 | **大号字幕同步跟读这句话**（默认静音也要看得懂）|
| **18–30s** | 纯录屏。确认页逐项读回 → 提交 → 状态卡出现 `系统派单中` → 变 `待出发` | App 的 TTS 播报原声 + 旁白 A | 旁白 A 字幕；状态卡出现时压角标：**系统派单中 → 待出发** |
| **30–45s** | 实拍。志愿者走近、两人握上牵引绳、起跑。中景 + 一个握绳特写 | 志愿者一句真实同期声（不写稿，现场抓）+ 旁白 B | 志愿者同期声字幕 + 旁白 B 字幕 |
| **45–58s** | 分屏：左边跑步实拍，右边手机上的服务中页面 | 旁白 C | 旁白 C 字幕；右屏出现时压角标：**进行中** |
| **58–68s** | 实拍。跑完，两人击掌 / 递水。切一下录屏的完成页 | **视障跑者本人的一句原声**（不写稿）| 跑者原声字幕；完成页压角标：**已完成** |
| **68–75s** | 定版。Logo + 一句话定位 + 内测入口 | 旁白 D | 助盲跑 · 内测招募中（+ 一个联系方式，只留一个 CTA）|

## 2. 旁白逐字稿

**总计 98 字，覆盖约 40 秒**（其余 35 秒交给同期声与环境音）≈ 150 字/分钟，正好是标准语速。

> **A（18–30s）**
> 说一句话，助盲跑就把预约建好了。每一步都会念出来，确认之后才提交。

> **B（30–45s）**
> 志愿者通过实名认证才能接单。

> **C（45–58s）**
> 服务中可以随时发起求助，系统记录事件并同步客服。行程也能由跑者自己分享给家人。

> **D（68–75s）**
> 助盲跑，让每一次出门都有人同行。

### 旁白里被刻意避开的说法（改了就会踩红线）

| 不能说 | 为什么 | 改成 |
|---|---|---|
| 「一键通知家属」「家人已收到提醒」 | 短信是事务提交后异步发的，失败**从不回告**跑者。App 永远不得宣称已送达 | 「行程**能由跑者自己**分享给家人」 |
| 「一键求助，救援马上到」 | 求助只记录事件、同步客服，**不派遣救援** | 「记录事件并同步客服」 |
| 「随时随地，现在就能跑」 | 下单起始时间距今必须 ≥30 分钟，**没有「现在就跑」** | 脚本里用「明天早上八点」 |
| 「AI 智能匹配最合适的志愿者」 | 没有配速/距离能力字段，匹配不按能力 | 不提匹配算法 |

## 3. 拍摄日执行顺序

**按风险和场地排，不按成片顺序排。** 音频风险最高的先拍完。

1. **音频试片（15 秒，最先做，不通过就别继续）**
   录一段「按住说话 → 识别 → 播报确认」，导出到 Photos 回放。
   已有开发者实证 `AVAudioEngine` voice processing 活跃期间 iOS 内置录屏**整段没有音频**，
   而语音下单正落在这个面上。**有声才继续，没声就改走 QuickTime 有线录制。**

2. **全部录屏（室内或安静处，两台设备）**
   - 设备 A = 盲人端，设备 B = 志愿者端，两台都登好、志愿者已开接单开关
   - 下单时间填 **T+31 分钟**（卡 30 分钟下限）
   - 下单成功后志愿者立刻接单，然后连续走 en-route → arrived → start-service → finish
   - ⚠️ **这条连续性未经真机验证**（30 分钟只卡下单，状态流转端点上没找到时间守卫，是 grep 结论）。
     **先空跑一遍确认能连着走完**，再正式录。走不通就分两次录、剪辑接起来
   - 同一流程录 **3 遍以上**

3. **跑道实拍（清晨，光线最好的一小时）**
   0–8s 的孤独镜头 → 30–45s 的会合起跑 → 58–68s 的跑完。**外接麦克风必须上**，风声是这类片子最大的毁片原因。

4. **空镜补拍（最后，有多少拍多少）**
   脚步、握绳特写、路面、手杖点地、水瓶。剪辑时救命的都是这些。

### 器材与设置

- 手机拍实拍够用，但**外接麦不能省**；三脚架
- 录屏前：静音勿扰开、通知清空、电量满、状态栏干净、亮度拉高
- 高德 key 要配进 `LocalConfig.xcconfig`，**没 key 时地图降级成占位图**，录出来是灰底方块

## 4. 出镜同意（拍摄当天，先于开机）

- **口头宣读 + 录像记录**，不要求视障跑者在看不见的纸上签字
- 讲清四件事：用途（官网 / 微信 / App Store / 内测宣传）、留存期限、撤回渠道、成片会先给本人过目
- 即使不拍脸也可能被识别 —— 体貌、住所背景、环境音都会暴露身份，剪辑时一并检查

## 5. 两个版本的导出

### 母版 → 官网 hero

```bash
ffmpeg -i master.mov -an -vf "scale=-2:1080" -c:v libx264 -crf 28 -preset slow \
  -pix_fmt yuv420p -movflags +faststart web-hero.mp4
```

`-an` **删掉整个音轨**（不是静音）—— 空音轨会挡自动播放。目标 ≤4MB 桌面 / ≤2MB 移动。
页面上用 `autoplay muted loop playsinline`，poster 图才是 LCP 元素，并且要给用户一个**能停止播放**的控件（WCAG 2.2.2）。

### 母版 → App Store 版（约 27 秒）

**删掉全部真人镜头**，只留 8–30s 那段录屏，补足到 15–30 秒。字幕加大（默认静音播放）。
封面帧默认取第 5 秒，挑一个信息量最大的画面，别落在转场中间。

```bash
ffmpeg -i appstore-cut.mov -vf "scale=886:1920:flags=lanczos" -r 30 \
  -c:v libx264 -profile:v high -level 4.0 -pix_fmt yuv420p -b:v 11M \
  -c:a aac -b:a 256k -ar 48000 -ac 2 -movflags +faststart appstore-preview.mp4
```

⚠️ 这版**必须有 AAC 立体声音轨**，与 hero 版正好相反 —— 两个版本不能共用同一个导出文件。

### 字幕

**硬字幕烧进画面**（平台会丢字幕轨），人工校对，自动生成的不够用。
官网页面上另放一份完整文字稿。
