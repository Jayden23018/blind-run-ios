# 05 — 页面规格

> 共 16 个页面。每个页面按 8 个维度描述：页面目标、入口、主要内容、主要操作、状态变化、错误状态、空状态、无障碍要求。

---

## 页面 1：登录页（手机号 + 验证码）

**页面目标**：用户通过手机号 + 验证码登录，首次登录自动创建账号。

**入口**：App 启动（无有效 token 时）。

**主要内容**：
- App Logo / 名称"助盲跑"
- 手机号输入框（11 位数字键盘，placeholder: "请输入手机号"）
- "获取验证码"按钮（手机号格式正确后启用）
- 验证码输入框（6 位，placeholder: "请输入验证码"）
- 验证码倒计时（60 秒，"重新发送"链接）
- 环境切换入口（底部或角落，不显眼：Mock / 本地 / 生产）

**主要操作**：
- 输入手机号 → 点击"获取验证码"
- 输入验证码 → 自动验证（6 位填完后自动提交，或手动点击"登录"）
- 点击"重新发送"（倒计时结束后显示）
- 点击环境切换

**状态变化**：
- 手机号格式校验中 → 实时提示格式错误
- "获取验证码"点击 → 页面提示"验证码已发送"，按钮变为倒计时（60 秒）
- 验证码输入 → 调用 `POST /api/auth/phone-login` 并跳转
- 首次登录 → 角色选择页
- 非首次登录 → 直接进入上次选择的角色首页

**错误状态**：
- 手机号格式错误 → 红框 + "请输入正确的手机号"
- 验证码错误 → 抖动 + "验证码错误，请重新输入"
- 网络错误 → Toast "网络错误，请重试"

**空状态**：无（登录页必然有输入框和按钮）。

**无障碍要求**：
- 手机号输入框：accessibilityLabel = "请输入11位手机号"
- 验证码输入框：accessibilityLabel = "请输入6位验证码"
- "获取验证码"按钮：accessibilityHint = "点击后发送验证码"
- TTS：进入页面不自动播报（避免打扰）

## 页面 2：角色选择页

**页面目标**：用户选择本次使用的角色（盲人跑者 / 志愿者）。

**入口**：首次登录验证码验证成功后 / 用户从设置主动切换角色。

**主要内容**：
- 标题："请选择您的角色"
- 两个大型卡片：
  - 盲人跑者卡片：图标、标题"我是盲人跑者"、副标题"预约志愿者陪我跑步"
  - 志愿者卡片：图标、标题"我是志愿者"、副标题"陪伴盲人跑者完成跑步"
- 底部提示："一个手机号可同时拥有两个身份，后续可在设置中切换"

**主要操作**：
- 点击"盲人跑者"卡片 → 进入盲人资料页（首次）或盲人首页
- 点击"志愿者"卡片 → 进入志愿者认证页（首次）或志愿者首页

**状态变化**：
- 选择后保存 activeRole 到后端和本地
- 如果有角色对应的活跃订单（accepted / arrived / in_progress / emergency），先弹窗拦截再决定

**错误状态**：
- 网络错误 → Toast "网络错误，请重试"
- 角色保存失败 → Toast "角色设置失败"

**空状态**：无。

**无障碍要求**：
- 每个角色卡片是单个 VoiceOver 元素，包含标题和副标题
- 盲人跑者卡片：accessibilityLabel = "我是盲人跑者，预约志愿者陪我跑步"
- 志愿者卡片：accessibilityLabel = "我是志愿者，陪伴盲人跑者完成跑步"

## 页面 3：盲人资料页

**页面目标**：盲人跑者填写个人资料和紧急联系人信息，完成注册。

**入口**：角色选择页选择"盲人跑者"（首次）/ 设置页 → 编辑资料。

**主要内容**：
- 标题："完善信息"
- 昵称输入框（必填）
- 紧急联系人姓名输入框（必填）
- 紧急联系人电话输入框（必填，11 位数字键盘）
- 跑步经验选择器（选填：无经验 / 偶尔跑 / 经常跑）
- "完成"按钮

**主要操作**：
- 填写所有必填项 → 点击"完成" → 保存到后端 → 进入盲人首页
- 选填跑步经验
- 已有资料时：预填已有数据

**状态变化**：
- 提交 → loading → 成功（跳转首页）
- 编辑模式（来自设置）：标题变为"编辑资料"，按钮文字变为"保存"

**错误状态**：
- 必填项为空 → 按钮禁用 + 空字段红框标记
- 手机号格式错误 → "请输入正确的手机号"
- 网络错误 → "保存失败，请重试"

**空状态**：无（首次使用时字段为空）。

**无障碍要求**：
- 每个输入框有清晰的 accessibilityLabel
- 必填字段标记为 accessibilityHint = "必填"
- 完成按钮：最小高度 64pt
- TTS：进入页面播报"请填写个人资料"

## 页面 4：盲人首页

**页面目标**：盲人跑者的功能入口，根据是否有活跃订单展示不同内容。

**入口**：登录成功 / 资料填写完成 / 服务完成返回。

**主要内容（无活跃订单时）**：
- 高德小地图（显示当前位置标记）
- "开始约跑"大按钮（最小高度 64pt，醒目颜色）
- 当前定位文字描述（如"当前位置：XXX路附近"）
- 底部操作栏：首页、设置、切换角色

**主要内容（有活跃订单时）**：
- 订单状态卡片（覆盖"开始约跑"按钮区域）：
  - 订单状态文字（匹配中 / 已接单 / 已到达 / 进行中）
  - 预约时间、出发地点
  - 志愿者信息（接单后显示昵称）
- 点击卡片进入对应订单详情页
- 高德小地图（显示订单地点标记）
- "重复当前状态"按钮

**主要操作**：
- 点击"开始约跑" → 创建预约页
- 点击订单状态卡片 → 对应订单状态页
- 点击"重复当前状态" → TTS 重新播报

**状态变化**：
- 无订单 → 有订单：UI 从"开始约跑"切换为订单卡片
- 有订单 → 无订单：UI 恢复"开始约跑"

**错误状态**：
- 定位失败 → 显示默认坐标位置
- 网络错误 → 页面仍然可用（地图显示缓存位置）

**空状态**（无活跃订单）：
- 显示"开始约跑"按钮 + 地图（当前位置），属于正常状态，非空状态。

**无障碍要求**：
- "开始约跑"按钮：最小高度 64pt，accessibilityLabel = "开始约跑"
- 订单状态卡片：accessibilityLabel = "当前订单：" + 订单状态中文
- TTS：进入页面播报"欢迎来到助盲跑"（无订单）或播报当前订单状态
- "重复当前状态"按钮：accessibilityLabel = "重复当前状态"

## 页面 5：创建预约页

**页面目标**：盲人跑者创建跑步预约订单。

**入口**：盲人首页 → 点击"开始约跑"。

**主要内容**：
- 出发地点选择（高德 POI 搜索 + 当前位置填充）：
  - 搜索输入框 + 麦克风按钮（语音输入）
  - POI 搜索结果列表
  - 默认填充当前位置
- 预约时间选择（DatePicker，不早于当前时间 + 30 分钟）
- 目的地 / 路线输入框（选填，带麦克风按钮）
- 预计跑步时长选择（选填：15 分钟 / 30 分钟 / 45 分钟 / 1 小时 / 1.5 小时 / 2 小时）
- 预计距离输入（选填，数字键盘，单位：公里）
- 配速偏好选择（选填：慢跑 / 中速 / 较快）
- 是否需要同性志愿者开关（选填）
- 备注输入框（选填，多行文本，带麦克风按钮）
- "提交预约"按钮

**主要操作**：
- 搜索/选择出发地点
- 选择预约时间
- 填写可选项
- 点击"提交预约" → 创建订单 → 订单状态等待页

**状态变化**：
- 定位初始化 → 自动填充当前位置
- 地点搜索 → 显示 POI 结果列表
- 提交 → loading → 成功跳转 / 失败提示

**错误状态**：
- 定位权限拒绝 → "需要开启定位权限才能创建预约" + "去设置"按钮
- 定位失败 → 使用默认测试坐标
- 预约时间不足 30 分钟 → "预约时间需至少在 30 分钟后"
- 出发地点为空 → "请选择出发地点"
- 网络错误 → "提交失败，请重试"

**空状态**：
- POI 搜索结果为空 → "未搜索到相关地点"

**无障碍要求**：
- 出发地点搜索框：accessibilityLabel = "搜索出发地点"
- 麦克风按钮：accessibilityLabel = "语音输入出发地点"
- 时间选择器：使用系统 DatePicker，可被 VoiceOver 访问
- 提交按钮：最小高度 64pt
- TTS：进入页面不自动播报，提交成功后播报"订单提交成功"

## 页面 6：盲人订单状态等待页

**页面目标**：展示订单当前状态，等待志愿者接单和到达。

**入口**：创建预约提交成功 / 盲人首页点击订单卡片。

**主要内容**：
- 大号状态指示器：
  - matching：动画旋转圆圈 + "匹配中，请稍候"
  - accepted：志愿者卡片（昵称）+ "已接单，志愿者正在赶来"
  - arrived：志愿者卡片 + "志愿者已到达约定地点"
- 订单信息卡片（出发地点、预约时间、可选项）
- "确认开始服务"按钮（仅 arrived 状态显示，最小 64pt）
- "取消订单"按钮（matching / accepted / arrived 状态显示，灰色/危险色）
- "一键求助"按钮（accepted / arrived 状态显示，红色醒目）
- "重复当前状态"按钮

**主要操作**：
- matching / accepted / arrived：点击"取消订单"（二次确认，选择固定取消原因）
- arrived：点击"确认开始服务"
- accepted / arrived：点击"一键求助"（二次确认）
- 点击"重复当前状态"

**状态变化**：
- 每 5 秒轮询 GET /api/orders/{orderId}
- matching → accepted：更新 UI + TTS "志愿者已接单"
- matching → cancelled：显示"抱歉，暂无志愿者" + TTS
- accepted / arrived → cancelled：显示"预约已取消" + TTS
- accepted → arrived：显示确认按钮 + TTS "志愿者已到达"
- arrived → in_progress：跳转服务中页面 + TTS "服务已开始"

**错误状态**：
- 网络错误 → 保留上次查询结果，静默重试
- 轮询接口异常 → Toast "获取订单状态失败"

**空状态**：不适用（订单已创建）。

**无障碍要求**：
- 状态文本：大号字体，高对比度
- TTS：每次状态变化自动播报
- "确认开始服务"按钮：最小 64pt，accessibilityLabel = "确认开始服务"
- "取消订单"按钮：二次确认弹窗 + accessibilityHint = "取消当前订单"
- "一键求助"按钮：红色醒目，accessibilityHint = "遇到紧急情况时点击求助"
- "重复当前状态"按钮：accessibilityLabel = "重复当前状态"

## 页面 7：盲人服务中页

**页面目标**：在服务进行中显示相关信息，提供求助入口。

**入口**：订单状态变为 in_progress 后自动跳转 / 盲人首页点击进行中订单。

**主要内容**：
- 页面标题："服务进行中"
- 志愿者信息卡片（昵称、联系电话 — 可点击拨打）
- 服务开始时间 / 已进行时长
- "一键求助"大按钮（红色醒目，最小高度 64pt）
- "重复当前状态"按钮

**主要操作**：
- 点击志愿者电话 → 系统拨号
- 点击"一键求助" → 弹窗确认 → 进入 emergency
- 点击"重复当前状态" → TTS 播报

**状态变化**：
- 每 5 秒轮询
- in_progress → completed：跳转完成/评分页 + TTS "服务已完成"
- in_progress → emergency：跳转紧急求助页 + TTS "已进入求助状态"

**错误状态**：
- 网络错误 → 保留当前 UI，静默重试
- 拨号失败 → "无法拨打电话"

**空状态**：不适用。

**无障碍要求**：
- 志愿者电话：accessibilityLabel = "拨打志愿者电话 " + 电话号码
- "一键求助"按钮：红色醒目，最小 64pt，accessibilityHint = "遇到紧急情况时点击求助，需要二次确认"
- TTS：进入页面播报"服务已开始，祝您跑步愉快"
- "重复当前状态"按钮：accessibilityLabel = "重复当前状态"

## 页面 8：盲人完成/评分页

**页面目标**：显示服务完成状态，提供评分入口。

**入口**：订单状态变为 completed 后自动跳转。

**主要内容**：
- 完成图标 / 动画
- 服务摘要（时长、志愿者昵称、出发地点）
- 星级评分（1-5 星，可点击选择）
- 文字反馈输入框（选填，多行，带麦克风按钮）
- "提交评价"按钮
- "跳过" / "返回首页"链接

**主要操作**：
- 选择星级
- 填写文字反馈
- 点击"提交评价" → 提交成功 → 返回首页
- 点击"跳过" → 直接返回首页

**状态变化**：
- 提交评分 → loading → 成功提示 → 返回首页
- 跳过评分 → 返回首页

**错误状态**：
- 评分提交失败 → Toast "提交失败，可稍后在服务记录中评价"

**空状态**：不适用。

**无障碍要求**：
- TTS：进入页面播报"服务已完成"
- 星级评分：accessibilityLabel = "第 N 颗星"，可逐颗选择
- 文字反馈：麦克风按钮可用
- "提交评价"按钮：最小高度 64pt
- "跳过"按钮：accessibilityLabel = "跳过评价，返回首页"

## 页面 9：志愿者资料认证页

**页面目标**：志愿者填写资料并完成 Mock 认证。

**入口**：角色选择页选择"志愿者"（首次）/ 设置页 → 编辑资料。

**主要内容**：
- 标题："志愿者认证"
- 昵称输入框（必填）
- 手机号显示（自动填充登录手机号）
- Mock 认证区域：
  - 提示文字："请完成以下认证步骤（Demo 版为模拟认证）"
  - Mock 认证按钮（模拟身份验证流程）
  - 认证状态显示（not_submitted / pending / approved / rejected，MVP Mock 认证成功后直接 approved）
- "提交"按钮

**主要操作**：
- 填写昵称
- 点击 Mock 认证按钮 → 模拟认证 → verificationStatus 变为 approved
- 点击"提交" → 保存资料 → 进入志愿者首页

**状态变化**：
- Mock 认证完成：verificationStatus = approved, adminReviewStatus = approved
- 可服务开关由志愿者首页单独控制，Mock 认证不自动开启 isAvailable

**错误状态**：
- 昵称为空 → "请填写昵称"
- 未完成认证 → "请先完成认证"
- 网络错误 → "保存失败"

**空状态**：无（首次使用时为空字段）。

**无障碍要求**：
- 昵称输入框：accessibilityLabel = "请输入昵称"
- Mock 认证按钮：accessibilityLabel = "开始模拟认证"
- 提交按钮：最小高度 64pt

## 页面 10：志愿者首页

**页面目标**：志愿者功能总览，查看附近订单、管理可服务状态。

**入口**：认证完成 / 登录（已有认证）/ 服务完成返回。

**主要内容**：
- 用户信息区（昵称、积分余额）
- 可服务开关（Toggle，新志愿者默认关闭，由用户手动开启；seed demo 账号可预置开启）
- 高德小地图（显示附近订单位置点）
- 附近订单列表（前 3 个，按距离排序）：
  - 每个卡片：盲人昵称、出发地点、距离、预约时间
- "查看全部订单"链接
- 底部标签栏：
  - 首页
  - 服务记录
  - 积分商城
  - 设置

**主要操作**：
- 切换可服务开关
- 点击订单卡片 → 订单详情页
- 点击"查看全部" → 订单列表页
- 点击切换角色 → 角色切换（检查活跃订单）

**状态变化**：
- 可服务开关切换：即时更新（API 调用）
- 订单列表：进入时加载，下拉刷新

**错误状态**：
- 定位权限拒绝 → 提示"需要开启定位权限"，阻断距离排序相关订单查看与接单流程
- 订单加载失败 → "加载失败，下拉重试"
- 网络错误 → 保留上次缓存数据

**空状态**：
- 无可用订单 → "暂无可用订单，请稍后再来"
- 可服务开关关闭 → 仍显示订单，但不能接单

**无障碍要求**：
- 可服务开关：accessibilityLabel = "可服务开关"，accessibilityHint = "关闭后其他用户看不到你的接单状态"
- 订单卡片：accessibilityLabel = 盲人昵称 + 距离 + 时间
- TTS：进入页面播报"附近有 N 个可接订单"或"暂无可用订单"

**页面目标**：展示所有可接订单（matching 状态），按距离排序。

**入口**：志愿者首页 → "查看全部订单" / 底部标签栏。

**主要内容**：
- 标题："可接订单"
- 订单列表（List / ScrollView，下拉刷新）：
  - 每项：盲人昵称、出发地点、距离、预约时间、备注预览
  - 按距离从近到远排序
- 可服务开关（顶部快捷切换）

**主要操作**：
- 点击订单 → 订单详情页
- 下拉刷新 → 重新加载列表
- 切换可服务开关

**状态变化**：
- 下拉刷新 → loading → 更新列表
- 某个订单被其他人接走 → 从列表移除（下次刷新时）

**错误状态**：
- 网络错误 → "加载失败，下拉重试"
- 定位不可用 → 提示"需要定位权限"，阻断距离排序相关订单查看与接单流程

**空状态**：

**无障碍要求**：
- 每个订单卡片：accessibilityLabel = "盲人：" + 昵称 + "，距离：" + 距离 + "，地点：" + 出发地点 + "，时间：" + 预约时间

## 页面 12：志愿者订单详情页

**页面目标**：展示订单完整信息，提供接单操作。

**入口**：订单列表页 → 点击订单卡片。

**主要内容（接单前）**：
- 订单基本信息（出发地点、预约时间、目的地/路线（如有）、预计时长（如有）、预计距离（如有）、配速偏好（如有）、是否需要同性志愿者（如有）、备注（如有））
- 盲人非敏感信息（昵称，**不含**联系电话）
- 高德地图：显示出发地点标记、当前志愿者位置、距离
- "接单"按钮（绿色醒目，最小高度 64pt）

**主要内容（接单后）**：
- 订单信息同上
- 盲人完整信息（昵称 + 联系电话，可点击拨打）
- "查看地图"按钮（显示高德地图出发点位置、当前位置和距离，不做路线导航）
- "我已到达"按钮
- "取消订单"按钮
- "一键求助"按钮

**主要操作**：
- 接单前：点击"接单" → 确认弹窗 → 接单成功
- 接单后：点击"查看地图" → 显示出发点位置、当前位置和距离
- 接单后：点击"我已到达" → 订单变为 arrived
- 接单后：点击"一键求助" → 二次确认 → emergency
- 接单后：点击"取消订单" → 二次确认 → 选择取消原因 → cancelled

**状态变化**：
- 接单：matching → accepted
- 到达：accepted → arrived
- 取消：accepted → cancelled
- 求助：accepted → emergency

**错误状态**：
- 接单失败（已被接） → "该订单已被其他志愿者接单" → 返回列表
- 接单失败（网络） → "接单失败，请重试"
- 地图显示失败 → "无法显示地图，请重试"

**空状态**：不适用（订单存在才有详情页）。

**无障碍要求**：
- "接单"按钮：最小高度 64pt，accessibilityLabel = "接单"，accessibilityHint = "确认接单后将显示盲人联系方式"
- "我已到达"按钮：最小高度 64pt，accessibilityLabel = "我已到达约定地点"
- "查看地图"按钮：accessibilityLabel = "查看出发点位置"
- "一键求助"按钮：红色醒目，需二次确认

## 页面 13：志愿者服务中页

**页面目标**：服务进行中管理页面。

**入口**：订单状态变为 accepted / arrived / in_progress 后进入。

**主要内容**：
- 订单状态指示
- 盲人信息卡片（昵称 + 联系电话，可拨打）
- 订单信息（出发地点、预约时间）
- 操作按钮：
  - accepted："我已到达"按钮
  - arrived 且盲人未确认时：等待盲人确认提示
  - in_progress："结束服务"按钮（最小 64pt）
  - accepted / arrived："取消订单"按钮
- "一键求助"按钮（红色醒目）
- 高德小地图（出发地点标记）

**主要操作**：
- accepted：点击"我已到达" → 订单变为 arrived
- accepted / arrived：点击"取消订单" → 二次确认 → 选择取消原因 → cancelled
- in_progress：点击"结束服务" → 确认弹窗 → 服务完成
- 点击"一键求助" → 二次确认 → emergency
- 点击盲人电话 → 系统拨号

**状态变化**：
- 每 5 秒轮询
- accepted → arrived（志愿者点击已到达）：UI 更新
- accepted / arrived → cancelled：跳转首页并显示取消结果
- arrived → in_progress（盲人确认后）：UI 更新
- in_progress → completed：跳转首页 + 显示"服务完成，获得 +100 积分"
- accepted / arrived / in_progress → emergency：跳转紧急求助页

**错误状态**：
- 网络错误 → 保留当前 UI，静默重试
- 结束服务失败 → "操作失败，请重试"

**空状态**：不适用。

**无障碍要求**：
- "我已到达"按钮：最小高度 64pt，accessibilityLabel = "我已到达约定地点"
- "取消订单"按钮：需二次确认，accessibilityHint = "服务开始前取消当前订单"
- "结束服务"按钮：最小高度 64pt，需二次确认
- "一键求助"按钮：红色醒目，最小高度 64pt，需二次确认
- TTS：进入 arrived 状态不自动播报（由盲人端播报）
- TTS：进入 in_progress 状态播报"服务已开始"
