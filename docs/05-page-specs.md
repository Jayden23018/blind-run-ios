# 05 — 页面规格

> 共 16 个页面。每个页面按 8 个维度描述：页面目标、入口、主要内容、主要操作、状态变化、错误状态、空状态、无障碍要求。
> Cloud contract note: API calls use `POST /api/auth/send-code`, `POST /api/auth/verify-code`,
> `POST /api/user/role`, and the canonical order statuses from `AGENTS.md` / `docs/07-api-contract.openapi.yaml`.
> Lower-case status names in older page examples are historical aliases only.

## 页面 1：登录页（手机号 + 验证码）

**页面目标**：用户通过手机号 + 验证码登录，首次登录自动创建账号。

**入口**：App 启动（无有效 token 时）。

**主要内容**：
- App Logo / 名称"助盲跑"
- 手机号输入框（11 位数字键盘，placeholder: "请输入手机号"）
- "获取验证码"按钮（手机号格式正确后启用）
- 验证码输入框（6 位，placeholder: "请输入验证码"）
- 验证码倒计时（60 秒，"重新发送"链接）
- 环境切换入口（底部或角落，不显眼：Mock / 本地 / 生产）

**主要操作**：
- 输入手机号 → 点击"获取验证码"
- 输入验证码 → 自动验证（6 位填完后自动提交，或手动点击"登录"）
- 点击"重新发送"（倒计时结束后显示）
- 点击环境切换

**状态变化**：
- 手机号格式校验中 → 实时提示格式错误
- "获取验证码"点击 → 页面提示"验证码已发送"，按钮变为倒计时（60 秒）
- 验证码输入 → 调用 `POST /api/auth/verify-code` 并跳转
- 首次登录 → 角色选择页
- 非首次登录 → 直接进入上次选择的角色首页

**错误状态**：
- 手机号格式错误 → 红框 + "请输入正确的手机号"
- 验证码错误 → 抖动 + "验证码错误，请重新输入"
- 网络错误 → Toast "网络错误，请重试"

**空状态**：无（登录页必然有输入框和按钮）。

**无障碍要求**：
- 手机号输入框：accessibilityLabel = "请输入11位手机号"
- 验证码输入框：accessibilityLabel = "请输入6位验证码"
- "获取验证码"按钮：accessibilityHint = "点击后发送验证码"
- TTS：进入页面不自动播报（避免打扰）

## 页面 2：角色选择页

**页面目标**：用户选择本次使用的角色（盲人跑者 / 志愿者）。

**入口**：首次登录验证码验证成功后 / 用户从设置主动切换角色。

**主要内容**：
- 标题："请选择您的角色"
- 两个大型卡片：
  - 盲人跑者卡片：图标、标题"我是盲人跑者"、副标题"预约志愿者陪我跑步"
  - 志愿者卡片：图标、标题"我是志愿者"、副标题"陪伴盲人跑者完成跑步"
- 底部提示："一个手机号可同时拥有两个身份，后续可在设置中切换"

**主要操作**：
- 点击"盲人跑者"卡片 → 进入盲人资料页（首次）或盲人首页
- 点击"志愿者"卡片 → 进入志愿者认证页（首次）或志愿者首页

**状态变化**：
- 选择后保存 activeRole 到后端和本地
- 如果有角色对应的活跃订单（PENDING_ACCEPT / DRIVER_EN_ROUTE / DRIVER_ARRIVED / IN_PROGRESS），先弹窗拦截再决定

**错误状态**：
- 网络错误 → Toast "网络错误，请重试"
- 角色保存失败 → Toast "角色设置失败"

**空状态**：无。

**无障碍要求**：
- 每个角色卡片是单个 VoiceOver 元素，包含标题和副标题
- 盲人跑者卡片：accessibilityLabel = "我是盲人跑者，预约志愿者陪我跑步"
- 志愿者卡片：accessibilityLabel = "我是志愿者，陪伴盲人跑者完成跑步"

## 页面 3：盲人资料页

**页面目标**：盲人跑者填写个人资料和紧急联系人信息，完成注册。

**入口**：角色选择页选择"盲人跑者"（首次）/ 设置页 → 编辑资料。

**主要内容**：
- 标题："完善信息"
- 昵称输入框（必填）
- 紧急联系人姓名输入框（必填）
- 紧急联系人电话输入框（必填，11 位数字键盘）
- 跑步经验选择器（选填：无经验 / 偶尔跑 / 经常跑）
- "完成"按钮

**主要操作**：
- 填写所有必填项 → 点击"完成" → 保存到后端 → 进入盲人首页
- 选填跑步经验
- 已有资料时：预填已有数据

**状态变化**：
- 提交 → loading → 成功（跳转首页）
- 编辑模式（来自设置）：标题变为"编辑资料"，按钮文字变为"保存"

**错误状态**：
- 必填项为空 → 按钮禁用 + 空字段红框标记
- 手机号格式错误 → "请输入正确的手机号"
- 网络错误 → "保存失败，请重试"

**空状态**：无（首次使用时字段为空）。

**无障碍要求**：
- 每个输入框有清晰的 accessibilityLabel
- 必填字段标记为 accessibilityHint = "必填"
- 完成按钮：最小高度 64pt
- TTS：进入页面播报"请填写个人资料"

## 页面 4：盲人首页

**页面目标**：盲人跑者的功能入口，根据是否有活跃订单展示不同内容。

**入口**：登录成功 / 资料填写完成 / 服务完成返回。

**主要内容（无活跃订单时）**：
- 无活跃订单状态摘要，说明当前可以创建新的陪跑预约
- "开始约跑"大按钮（最小高度 64pt，醒目颜色）
- "重复当前状态"按钮
- 当前定位文字描述（如"当前位置：已获取设备定位"）
- 辅助高德小地图（显示当前位置标记，必须在状态、主操作和重复状态之后）
- 底部操作栏：首页、设置、切换角色

**主要内容（有活跃订单时）**：
- 订单状态卡片（覆盖"开始约跑"按钮区域）：
  - 订单状态文字（系统派单中 / 待出发 / 志愿者已到达 / 进行中）
  - 预约时间、出发地点
  - 志愿者信息（接单后显示昵称）
- 点击卡片进入对应订单详情页
- "查看当前订单"按钮
- "重复当前状态"按钮
- "取消订单"按钮（订单状态可取消时显示，包含 REMATCHING）
- 当前定位或订单出发点文字摘要
- 辅助高德小地图（显示订单地点标记，必须在状态、主操作、重复状态和取消动作之后）

**主要操作**：
- 点击"开始约跑" → 创建预约页
- 点击订单状态卡片 → 对应订单状态页
- 点击"取消订单" → 二次确认 → `POST /api/orders/{id}/cancel`
- 点击"重复当前状态" → TTS 重新播报

**状态变化**：
- 无订单 → 有订单：UI 从"开始约跑"切换为订单卡片
- 有订单 → 无订单：UI 恢复"开始约跑"；REMATCHING 取消成功后也返回无活跃订单状态

**错误状态**：
- 定位失败 → 明确显示"使用演示坐标"或"正在获取设备定位"，不得暗示已获得真实会合点
- 网络错误 → 页面仍然可用（地图显示缓存位置）

**空状态**（无活跃订单）：
- 显示无订单状态摘要 + "开始约跑"按钮 + "重复当前状态" + 辅助地图，属于正常状态，非空状态。

**无障碍要求**：
- "开始约跑"按钮：最小高度 64pt，accessibilityLabel = "开始约跑"
- 订单状态卡片：accessibilityLabel = "当前订单：" + 订单状态中文
- "取消订单"按钮：最小高度 64pt，需二次确认，accessibilityHint = "需要确认后取消当前订单"
- 辅助地图：accessibilityLabel 必须包含"辅助地图"或"辅助位置确认"，不得成为首个有意义 VoiceOver 元素
- TTS：进入页面播报"欢迎来到助盲跑"（无订单）或播报当前订单状态；复述需包含当前位置/出发地点的可理解摘要
- "重复当前状态"按钮：accessibilityLabel = "重复当前状态"

## 页面 5：创建预约页

**页面目标**：盲人跑者创建跑步预约订单。

**入口**：盲人首页 → 点击"开始约跑"。

**主要内容**：
- 引导步骤 1：确认出发地点
  - 当前出发地点文本摘要先于地图展示
  - 可保留默认当前位置，也可通过高德 POI 搜索选择地点
  - 搜索输入框 + 麦克风按钮（语音输入）
  - POI 搜索结果列表（显示地点名称和地址，不显示原始经纬度）
  - 辅助高德地图位于文字摘要、搜索和结果之后，只用于视觉确认
- 引导步骤 2：预约时间选择（DatePicker，不早于当前时间 + 30 分钟）
- 引导步骤 3：跑步需求（全部选填）
  - 路线备注输入框（带麦克风按钮）
  - 预计跑步时长选择（15 分钟 / 30 分钟 / 45 分钟 / 1 小时 / 1.5 小时 / 2 小时 / 不填写）
  - 配速偏好选择（走跑结合 / 轻松 / 中等 / 快速 / 无偏好）
  - 路线偏好选择（公园步道 / 街道 / 跑道 / 无偏好）
  - 本次携带导盲犬开关
  - 特殊说明输入框（选填，多行文本，带麦克风按钮）
- 引导步骤 4：确认并提交
  - 汇总出发地点、预约时间和已填写的选填需求
  - 未填写的选填字段不显示在确认摘要或复述语音中
  - "提交预约"按钮（最小高度 64pt）

**主要操作**：
- 每一步点击"下一步"进入后续步骤；不满足必填条件时显示并播报阻塞原因
- 点击"重复当前状态" → 播报当前步骤、当前值、下一步动作和阻塞错误
- 点击"提交预约" → 创建订单 → 订单状态等待页

**状态变化**：
- 定位初始化 → 自动填充当前位置
- 地点搜索 → 显示 POI 结果列表；语音识别结束且识别文本非空时自动搜索
- 步骤切换 → 只播报新步骤摘要，不在每次输入或 DatePicker 调整时自动长播报
- 提交 → loading → 成功跳转 / 失败提示

**错误状态**：
- 定位权限拒绝 → "需要开启定位权限才能创建预约" + "去设置"按钮
- 定位失败 → 使用默认测试坐标时明确标注"演示坐标"，不得暗示是真实出发点
- 预约时间不足 30 分钟 → "预约时间需至少在 30 分钟后"
- 出发地点为空 → "请选择出发地点"
- 网络错误 → "提交失败，请重试"

**空状态**：
- POI 搜索结果为空 → "未搜索到相关地点"

**无障碍要求**：
- 出发地点搜索框：accessibilityLabel = "搜索出发地点"
- 麦克风按钮：accessibilityLabel = "语音输入出发地点"
- 语音识别中：搜索按钮显示并播报"语音识别中"，识别成功后自动搜索地点
- 搜索结果：VoiceOver 播报结果数量和第一个地点名称，结果项读出地点名称和地址
- 时间选择器：使用系统 DatePicker，可被 VoiceOver 访问
- 辅助地图：accessibilityLabel 必须说明"辅助位置确认"，不得朗读原始经纬度
- 下一步 / 提交按钮：最小高度 64pt
- TTS：进入页面不自动播报，提交成功后播报"订单提交成功"

## 页面 6：盲人订单状态等待页

**页面目标**：展示订单当前状态，等待系统派单、志愿者接单和到达。

**入口**：创建预约提交成功 / 盲人首页点击订单卡片。

**主要内容**：
- 大号状态指示器：
  - PENDING_MATCH：动画旋转圆圈 + "系统正在为你派单，请稍候"
  - PENDING_ACCEPT：志愿者卡片 + "待出发"，提示按预约时间前往或等待在出发地点
  - DRIVER_EN_ROUTE：志愿者卡片 + "志愿者已出发，正在前往出发地点"
  - DRIVER_ARRIVED：志愿者卡片 + "志愿者已到达约定地点，等待志愿者开始服务"
- 订单信息卡片（出发地点、预约时间、可选项）
- 志愿者距离（收到位置且订单有出发坐标时）：显示"志愿者距出发地点约 X"，来源为志愿者最新 WebSocket 位置到订单出发坐标
- "取消订单"按钮（PENDING_MATCH / PENDING_ACCEPT / REMATCHING 状态显示，灰色/危险色）
- 当前 release 不显示"一键求助"或"紧急求助"入口
- "重复当前状态"按钮

**主要操作**：
- PENDING_MATCH / PENDING_ACCEPT / REMATCHING：点击"取消订单"（二次确认）
- 点击"重复当前状态"

**状态变化**：
- 每 5 秒轮询 GET /api/orders/{orderId}
- PENDING_MATCH → PENDING_ACCEPT：更新 UI 为"待出发" + TTS "志愿者已接单"，并朗读预约时间和出发地点，提示前往或等待在出发地点
- PENDING_MATCH → CANCELLED / NO_VOLUNTEER：显示"暂时没有可用志愿者" + TTS
- PENDING_ACCEPT / REMATCHING → CANCELLED：显示"预约已取消" + TTS
- REMATCHING → CANCELLED：后端已确认 `/api/orders/{id}/cancel` 接受该状态；iOS 仅调用现有取消接口，请求必须使用盲人 token，志愿者 token 不适用
- PENDING_ACCEPT → DRIVER_EN_ROUTE：更新状态 + TTS "志愿者已出发，正在前往出发地点"
- DRIVER_EN_ROUTE → DRIVER_ARRIVED：更新状态 + TTS "志愿者已到达"
- DRIVER_ARRIVED → IN_PROGRESS：跳转服务中页面 + TTS "服务已开始"

**错误状态**：
- 网络错误 → 保留上次查询结果，静默重试
- 轮询接口异常 → Toast "获取订单状态失败"

**空状态**：不适用（订单已创建）。

**无障碍要求**：
- 状态文本：大号字体，高对比度
- TTS：每次状态变化自动播报；PENDING_MATCH 播报"预约已提交，系统正在为你派单"
- "取消订单"按钮：二次确认弹窗 + accessibilityHint = "取消当前订单"
- 当前 release 不显示"一键求助"或"紧急求助"按钮；后续安全专项恢复时必须补二次确认和 TTS
- "重复当前状态"按钮：accessibilityLabel = "重复当前状态"

## 页面 7：盲人服务中页

**页面目标**：在服务进行中显示相关信息；当前 release 隐藏求助入口。

**入口**：订单状态变为 IN_PROGRESS 后自动跳转 / 盲人首页点击进行中订单。

**主要内容**：
- 页面标题："服务进行中"
- 志愿者信息卡片（昵称、联系电话 — 可点击拨打）
- 服务开始时间 / 已进行时长
- 当前 release 不显示"一键求助"或"紧急求助"入口
- "重复当前状态"按钮

**主要操作**：
- 点击志愿者电话 → 系统拨号
- 点击"重复当前状态" → TTS 播报

**状态变化**：
- 每 5 秒轮询
- IN_PROGRESS → COMPLETED：跳转完成/评分页 + TTS "服务已完成"
- IN_PROGRESS：订单状态保持不变，等待志愿者结束服务或取消

**错误状态**：
- 网络错误 → 保留当前 UI，静默重试
- 拨号失败 → "无法拨打电话"

**空状态**：不适用。

**无障碍要求**：
- 志愿者电话：accessibilityLabel = "拨打志愿者电话 " + 电话号码
- 当前 release 不显示求助入口；未来恢复时求助按钮需最小 64pt、二次确认、清晰 accessibilityHint 和 TTS
- TTS：进入页面播报"服务已开始，祝您跑步愉快"
- "重复当前状态"按钮：accessibilityLabel = "重复当前状态"

## 页面 8：盲人完成/评分页

**页面目标**：显示服务完成状态，提供评分入口。

**入口**：订单状态变为 COMPLETED 后自动跳转。

**主要内容**：
- 完成图标 / 动画
- 服务摘要（时长、志愿者昵称、出发地点）
- 星级评分（1-5 星，可点击选择）
- 文字反馈输入框（选填，多行，带麦克风按钮）
- "提交评价"按钮
- "跳过" / "返回首页"链接

**主要操作**：
- 选择星级
- 填写文字反馈
- 点击"提交评价" → 提交成功 → 返回首页
- 点击"跳过" → 直接返回首页

**状态变化**：
- 提交评分 → loading → 成功提示 → 返回首页
- 跳过评分 → 返回首页

**错误状态**：
- 评分提交失败 → Toast "提交失败，可稍后在服务记录中评价"

**空状态**：不适用。

**无障碍要求**：
- TTS：进入页面播报"服务已完成"
- 星级评分：accessibilityLabel = "第 N 颗星"，可逐颗选择
- 文字反馈：麦克风按钮可用
- "提交评价"按钮：最小高度 64pt
- "跳过"按钮：accessibilityLabel = "跳过评价，返回首页"

## 页面 9：志愿者资料认证页

**页面目标**：志愿者通过基本信息与身份证二要素核验、动作活体认证直接完成主注册流程。

**入口**：角色选择页选择"志愿者"（首次）/ 设置页 → 编辑资料。

**主要内容**：
- 标题："志愿者认证"
- 昵称输入框（必填）
- 手机号显示（自动填充登录手机号）
  - 认证区域：
  - 提示文字："请完成以下认证步骤（Demo 版为模拟认证）"
  - 基本信息与身份证二要素、动作活体认证入口
  - 两步进度显示：基本信息与身份核验、活体认证
  - 主注册状态显示（STEP_1_BASIC_INFO / STEP_3_FACE_VERIFY / STEP_4_COMPLETED；STEP_4_TRAINING 仅为遗留兼容状态）
- "提交"按钮

**主要操作**：
- 填写昵称
- 点击开始认证 → 进入志愿者注册流程 → 填写基本信息、与身份证一致的姓名和身份证号码 → 后端完成身份证二要素核验 → init 获取 certifyId → iOS 通过 AliyunFaceAuthFacade 原生 SDK 完成动作活体 → SDK 回调后轮询 result → 后端直接完成注册
- 点击"提交" → 保存资料 → 进入志愿者首页

**状态变化**：
- 身份证二要素核验不通过：停留 STEP_1_BASIC_INFO，显示后端错误并允许更新身份证信息
- 身份证二要素核验通过：currentStep = STEP_3_FACE_VERIFY，进入动作活体认证
- 动作活体认证 init 返回 PENDING 和非空 certifyId：iOS 向原生 SDK 传入 certifyId 和当前 ViewController，用户按 SDK 页面提示完成动作后前端轮询 result；原生流程不要求 certifyUrl
- 活体认证通过：后端原子设置 currentStep = STEP_4_COMPLETED、canAcceptOrders = true；新注册不得进入 STEP_4_TRAINING
- 活体 result 已通过但 status 尚未完成：显示“活体已通过，注册状态同步中，无需课程或答题”，每 5 秒轮询并提供手动刷新，不允许重复发起活体认证
- status 返回 STEP_4_COMPLETED、遗留 STEP_4_TRAINING 或 canAcceptOrders = true：显示并播报“注册完成，请返回首页开启可服务状态”
- STEP_4_TRAINING 仅用于旧账号或尚未升级后端的兼容；iOS 将其按主注册完成处理并停止轮询，但不会自动开启可服务状态
- 可选资质证书上传使用 `/api/volunteer/verification`，不属于主注册引导链路，不影响接单资格
- 可服务开关由志愿者首页单独控制，认证不自动开启 isAvailable / wantsDispatch
- 提交：loading → 成功跳转

**错误状态**：
- 昵称为空 → "请填写昵称"
- 未完成主注册流程 → "请先完成志愿者注册流程"
- 身份证二要素失败 → 显示后端失败原因并允许重新提交 Step1
- 活体认证发起时返回身份信息错误 → 允许返回 Step1 修改姓名和身份证号码后重新提交
- 原生 SDK 用户取消 → 留在活体认证步骤，清除本次 certifyId 并允许重新发起
- 原生 SDK 系统、网络或设备时间错误 → 显示对应原因，清除本次 certifyId 并允许重新发起
- 原生 SDK 返回 1001 → 仅展示根据白名单 subcode 映射的提示和安全错误码；不得展示原始 SDK message、certifyId、metaInfo 或身份字段
- Z1014/Z1023 → SDK 初始化或内部处理失败；I4001 → 刷脸模块接入异常；Z1010/Z1037 → 认证参数或流程配置异常；Z1001/Z1002/Z1020 → 相机不可用；Z1024 → 流程重复发起
- 活体认证拒绝 → 显示 faceVerifyRejectionReason 或 result.message，并允许重新发起
- 活体认证通过但 status 仍未进入 STEP_4_TRAINING / STEP_4_COMPLETED 且 canAcceptOrders 不为 true → 保持同步等待，禁止课程/答题入口和重复活体认证
- 网络错误 → "保存失败"

**空状态**：无（首次使用时为空字段）。

**无障碍要求**：
- 昵称输入框：accessibilityLabel = "请输入昵称"
- 认证按钮：accessibilityLabel = "开始认证"
- 注册完成结果：accessibilityLabel = "注册完成，请返回首页开启可服务状态"

## 设置页：退出与账户删除

- 盲人跑者和志愿者设置页均提供“退出登录”和“删除账户”。
- 退出登录保留既有二次确认；请求中禁用重复提交。撤销失败时显示并朗读原因，允许重试，或再次确认“仅退出本机”，且明确远端 Token 可能仍有效。
- 删除账户使用两阶段破坏性确认，说明历史数据软删除、全部 Token 失效及手机号可重新注册；不存在“仅本机删除”。
- 阻断状态为 `PENDING_MATCH`、`PENDING_ACCEPT`、`DRIVER_EN_ROUTE`、`DRIVER_ARRIVED`、`IN_PROGRESS`、`REMATCHING`。

## 全局前台实时通知层

**页面归属**：位于 `ContentView` 根层级，覆盖盲人/志愿者导航但不归属某个功能页。

**显示规则**：

- 显示可选标题、安全正文、优先级图标和“关闭”按钮；不展示原始 payload、坐标或内部 event key。
- `HIGH` 立即抢占正在显示的 `NORMAL`，被抢占普通通知回到最多 24 条的内存队列；同优先级按到达顺序展示。队列溢出时依次淘汰最早的 `NORMAL`、非安全 `HIGH`，仅当队列全部为安全事件时淘汰最早安全事件，以优先保留较新的安全提醒。
- 可见正文、合并后的 VoiceOver label 和 TTS 使用同一安全语义；关闭按钮提示会继续显示下一条。
- 活动订单的生命周期模板通知不直接展示/播报，由订单详情刷新后的本地状态文案替代。
- 派单 overlay 保持志愿者现有接受/拒绝和倒计时 UI，但数据源改为 app-lifetime retained prompt，导航不得重置后端截止时间。

**边界**：本层不提供 peer marker、分离操作、紧急操作、通知收件箱或后台推送。
