# 语音下单真机手测脚本（OpenSpec 任务 5.5）

> 对应 `openspec/changes/enable-one-utterance-booking/tasks.md` 的 `5.5`。
> **这份脚本存在的理由**：自动化测试跑通不等于语音链路可用。484 条单测全绿，但没有一条
> 让真人对着麦克风说过话。2026-08-05 刚改的两处——尾静音 12 秒 → 2 秒、确认词白名单
> 19 条 → 8 条——**只有真人说话才能验**，单测证明不了「2 秒会不会切断中文长句」和
> 「8 个词够不够用」。

## 0. 前置条件（不满足就别开始，否则测的是别的东西）

| 项 | 要求 | 怎么确认 |
|---|---|---|
| 设备 | 真机。模拟器**永久不可用**（高德 SDK 无 arm64-sim slice） | — |
| 屏幕 | 解锁 + 自动锁定设为「永不」 | 设置 → 显示与亮度 → 自动锁定 |
| 环境 | **演示云端**，不是 Mock | 设置页环境切换器（仅 DEBUG 可见）。Mock 不打真实解析端点，测了等于没测 |
| VoiceOver | **开** | 设置 → 辅助功能 → VoiceOver。这是目标用户的真实条件，关着测出来的结论不算 |
| 定位 | **真实 GPS 定位已获取**（室外或窗边） | 2026-08-05 起演示坐标不再兜底成起点，室内冷启动会让起点缺失 |
| 六道门槛 | 基本资料 / 实名 / 紧急联系人 / 定位权限全部满足 | 进预约页会自动播报第一个缺的（P0-3 新增），听到就先去补 |
| 环境噪音 | 安静房间跑一遍，**再到室外或有人说话的环境跑一遍** | 案例 C 与 E 依赖这个 |

**准备一支笔和纸**，或另一台设备录音。VoiceOver 开着时不方便在手机上记录。

## 0.5 🛑 阻断：三个语音端点线上返回 404，本脚本当前跑不了

**2026-08-05 实测**（盲人测试账号 `18664945138`，带有效 JWT）：

```
POST /api/orders/voice/parse
{"success":false,"code":404,"errorCode":"NOT_FOUND","message":"请求的资源不存在"}

同一路径不带 token → 401
```

401 与 404 分属两层：401 说明鉴权在工作，**404 是过了鉴权之后没有 handler 匹配**，
且用的是应用自己的错误信封（不是 nginx 裸 404）。`parse` / `parse-slot` / `resolve-address`
三条全是这个结果。

**不是没实现，是没部署**：后端源码里 `VoiceOrderController.java` 存在且映射正确
（`@RequestMapping("/api/orders/voice")` + `@PostMapping("/parse")`），但那些提交在
分支 `fix/voice-order-timezone-geocoding` 上，线上跑的是不含这些端点的旧构建。

### 这会让手测得出**误导性**结论，而不是明显失败

`VoiceOrderWizard.parseFreeform` 用 `try?` **吞掉所有解析错误**（`VoiceOrderWizard.swift:328`，
注释里写明这是刻意的：整句抽不出或网络挂了都不该把用户打回表单）。所以在今天的线上：

1. 用户说「明天早上八点从人民广场出发跑一个小时」
2. `parse` 返 404 → `try?` → `parsed = nil` → **一个槽位都没填**
3. 读回念的是**默认值**（时间≈30 分钟后、时长默认档），而不是用户说的内容
4. 没仔细听的人说「确认」，就下了一张时间地点全错的单

设计上唯一的防线是读回会先念原话再念整单，两者对不上就能听出来——这条防线是有效的，
但它是为**偶发**失败设计的，不是为「端点恒 404」设计的。

### 2026-08-06 复核：两处订正

**订正一：不是三条全 404，只有 `/parse` 一条。** 上面「`parse` / `parse-slot` / `resolve-address`
三条全是这个结果」这句是从一条推广到三条的误记。查后端 git 的结论是：

| 端点 | 引入 commit | 在生产构建（`7bce0b3`）里？ |
|---|---|---|
| `/resolve-address` | `9a12efa`（2026-07-24） | ✅ 在 |
| `/parse-slot` | `9a12efa`（2026-07-24） | ✅ 在 |
| `/parse` | `7cb5758`（2026-08-05 09:57） | ❌ 只在 `fix/voice-order-timezone-geocoding` |

`git branch --contains 7cb5758` 只返回那一个分支；`main` 的 `VoiceOrderController.java` 只有
`/resolve-address` 与 `/parse-slot` 两个 `@PostMapping`，`SecurityConfig.java:126` 的放行列表同样只有三条不含
`/parse`。所以**今天生产的真实形态是「整句轮全默认值 + 逐项修改轮正常工作」**，不是整条语音链路瘫痪。

⚠️ 无鉴权探测复核不了这个结论：Spring Security 的 filter 在 DispatcherServlet 之前，
假路径 `/api/orders/voice/definitely-not-real` 同样返 401 同样的信封。要用探测定论必须带 BLIND 角色的 JWT。

**订正二：现在有信号了。** `parseFreeform` 已从 `try?` 改为 `do/catch`，解析失败时在读回**之前**先说一句
`VoiceOrderWizard.parseFailureNotice`（「这次没能把你说的话转成预约内容，下面念的是默认值。」），
不重问、不打回表单。守卫用例 `VoiceOrderWizardTests.testFreeformAnnouncesThatParsingFailedBeforeReadingBackDefaults`。

> 因此案例 B（一句话成单）现在跑出来的是「默认值链路 + 失败提示」——**这本身就是一条要验的行为**：
> 听到那句提示才算通过，静默念默认值算失败。C（长句尾静音）、D（确认词）、F 仍需 `/parse` 部署后才能真正验。
> A（唤起可感知）、G（权限降级）、H（门槛播报）、I（演示坐标阻断）不依赖解析端点，随时可跑。
> **仍要催后端把 `7cb5758` 部署上去。**

## 1. 判别法：先分清「后端没配 key」和「它没听懂」

后端 `AmapGeocodingService` 在 `amap.web.key` 为空时**静默返回 empty**
（`AmapGeocodingService.java:65`），不报错、不给错误码。表现出来就是「地点识别不出来」，
极容易被误诊成识别问题，然后浪费一整轮手测。

**判别规则（零成本，跑案例 B 时顺便看）：**

| 现象 | 结论 |
|---|---|
| 时间对、时长对，**只有地点恒缺**（`missing: ADDRESS`），换任何地名都一样 | **后端 `AMAP_WEB_KEY` 没配**。停止手测，去后端确认，不要继续 |
| 三个槽位有对有错，换个说法能对 | 正常的识别/解析问题，继续测 |

> （`retryAfterSeconds=86400`），`13800000003` 的 `000000` 无效（不在当前白名单）。

## 2. 测试用例

每个案例记三件事：**① 我说了什么 ② 它念了什么 ③ 结果对不对**。

### A. 唤起与录音可感知（不看屏幕能不能知道麦克风开了）

1. 首页 → 「开始约跑」
2. 闭眼，或把屏幕转开

**要听到 / 感到**：提示音 → 提问「请说你想从哪儿出发、什么时候跑、跑多久，比如：明天早上八点从人民广场出发跑一个小时。说完再点一下就好。」

| 检查 | 通过标准 |
|---|---|
| 起音提示 | 能听见或感到，且能和播报本身区分开 |
| 从按下到能开口说话 | 主观上不超过 1 秒；超过要有占位语音，不能静默 |
| 录音开始的时刻 | **不看屏幕能确定**。说不清「它什么时候开始听我说话」就是不通过 |

### B. 一句话成单（主路径，同时计时）

**说**：「明天早上八点从人民广场出发跑一个小时」

**开始计时**：从按下「开始约跑」那一刻。

| 节点 | 记录 |
|---|---|
| 说完到读回开始 | ___ 秒（含 2 秒尾静音 + 解析往返） |
| 读回全文 | 逐字记下来 |
| 读回时长 | ___ 秒 |
| 说「确认」到听见成单 | ___ 秒 |
| **总计** | ___ 秒 |

**读回必须是三段**：① 你刚才说的原话 ② 解析出的整单（地点 / 绝对时间 / 时长）
③ 出路「说「确认」就下单；要改就说「改地点」「改时间」或者「改时长」。」

| 检查 | 通过标准 |
|---|---|
| 三段齐全 | 少任何一段都不通过。念原话是为了让人分得清「我说错了」和「它听错了」 |
| 时间念的是绝对时间 | 「明天早上八点」要念成具体日期时间，不能原样复述 |
| 地点念的是解析后的地名 | 不能只念转录文本 |
| **总时长** | ≤60 秒。超了记下卡在哪一段 |

### C. 2 秒尾静音会不会切断中文长句 ⚠️ 本次改动重点

尾静音从 12 秒降到 2 秒（`SpeechInputService.swift`）。依据是自发语音停顿的第三个峰在
1500ms，2 秒盖住它留 500ms 余量。**这个推导来自英文语料，中文没有对应研究**——所以必须实测。

分别说下面三句，**每句在标注的位置刻意停顿一下**：

| # | 说什么 | 停顿位置 | 被截断了吗 |
|---|---|---|---|
| C1 | 明天早上八点……从人民广场出发……跑一个小时 | 两处省略号 | ☐ 是 ☐ 否 |
| C2 | 那个……我想想……明天下午三点从徐家汇跑四十分钟 | 前两处 | ☐ 是 ☐ 否 |
| C3 | 后天上午十点，从我家附近的公园，大概跑半小时吧 | 逗号处 | ☐ 是 ☐ 否 |

**再做一次「慢速版」**：找一位说话慢的人（或刻意放慢到平时的一半）说 C1。

| 检查 | 通过标准 |
|---|---|
| 被截断次数 | 6 次尝试中被截断 **0～1 次**算通过 |
| 被截断 ≥2 次 | **不通过**。记下被截在哪个字，回来把 2 秒调到 2.5 或 3 秒 |
| 说完后干等的感觉 | 不应有。若觉得「说完了它怎么还不理我」，说明 2 秒还是长了 |

> 被截断时的补救通道要一并验：整块内容区可点结束、两指双击（Magic Tap）也能结束。
> 这两条现在就有，不依赖静音兜底。

### D. 8 个确认词够不够用 ⚠️ 本次改动重点

现行白名单**只有 8 个**：
`确认` `确认下单` `确认预约` `确认提交` `没问题` `就这样` `就这么办` `开始约跑`

走到读回之后，**不看提示、凭直觉**说一个肯定词。连做 5 次（每次重新走一遍到读回）。

| # | 我脱口而出说的 | 成单了吗 |
|---|---|---|
| 1 | ______ | ☐ 是 ☐ 否 |
| 2 | ______ | ☐ 是 ☐ 否 |
| 3 | ______ | ☐ 是 ☐ 否 |
| 4 | ______ | ☐ 是 ☐ 否 |
| 5 | ______ | ☐ 是 ☐ 否 |

| 检查 | 通过标准 |
|---|---|
| 5 次里有 ≥4 次直接命中 | 通过 |
| ≤3 次命中 | 记下没命中的那几个词。**先别急着加回白名单**——被移出的「好 / 行 / 对 / 是」是有明确事故依据的，要加也只能加多音节的 |
| 读回念的出路 | 必须是「说「确认」就下单」，且照着念**一定**要生效。这一句和白名单是绑定的，不一致就是缺陷 |

### E. 旁人说话不能下单 ⚠️ 本次改动重点，需要第二个人

这是收窄白名单的**全部理由**。2018 年 Portland 的 Alexa 事故就是背景对话里一句 "right"
满足了确认。一对一陪跑里志愿者就站在旁边。

走到读回之后，**你自己不说话**，让旁边的人正常音量说：

| # | 旁人说 | 下单了吗（必须是「否」） |
|---|---|---|
| E1 | 好 | ☐ |
| E2 | 行吧 | ☐ |
| E3 | 对 | ☐ |
| E4 | 好啊我知道了 | ☐ |
| E5 | 对了你等一下 | ☐ |
| E6 | 是这样没错 | ☐ |

| 检查 | 通过标准 |
|---|---|
| 六条全部**没有**下单 | 通过 |
| 任何一条下了单 | **CRITICAL，阻断发布**。立刻记下完整转录文本 |

### F. 定点修改

走到读回后，依次试：

| 说什么 | 应该发生 |
|---|---|
| 改时间 | 只重问时间，**不要求重说地点和时长**，改完重念整单 |
| 改地点 | 同上 |
| 改时长 | 同上 |
| 再说一遍 | 重念整单，不推进 |
| 我要改一下 | 不推进、不下单，重问（这是「听不懂」的正确表现） |

### H. 门槛播报（P0-3 新增，本次改动）

先去设置里**删掉紧急联系人**，然后：

1. 首页 → 「开始约跑」（语音路径）→ 应立刻播报紧急联系人那条门槛，不进录音
2. 从表单入口进预约页 → **进页面就应播报同一条**，不是填完四步才说

| 检查 | 通过标准 |
|---|---|
| 两条路径都在进页面时播报 | 通过。表单路径以前要填完四步才说，这次改的就是它 |
| 播报内容 | 要给出能走通的下一步（去哪个页面补），不能只说「不行」 |

**测完记得把紧急联系人加回去。**
