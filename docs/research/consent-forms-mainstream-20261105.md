# 敏感信息单独同意用什么形态：整页、小弹窗还是勾选框（2026-11-05）

起因：负责人真机体验后说同意条款「每做一步就需要同意一次」「展示的形式和市面上主流的 app 也不一样」，主流是「一个小弹窗」或「最底下勾选是否同意」（Jayden23018/blind-run-ios#769）。

## 结论

- 法规与国标**没有**规定单独同意必须用整页、弹窗或勾选框中的哪一种。硬要求是：先告知再同意、明示同意、不默认勾选、不与其他事项打包、拒绝后不频繁再问、提供撤回方式、人脸要给替代方式。
- 国标解读明确允许「同一目的的多项敏感信息在一个表单页面一并告知、一次取得单独同意」⇒ 表单底部勾选框站得住。
- App Store 5.1.2(i) 要求把个人数据交给第三方（含 third-party AI）前披露并取得 explicit permission，没有规定形态 ⇒ 写清「发什么、发给谁」的小弹窗可以满足（这是推断，置信度中）。
- iOS 系统定位授权框的用途文字可自定义，法规的「申请权限时同步告知目的」可以直接写在里面，不一定要多弹一层。
- ⚠️ **各家 App 的真实界面没有拿到一手证据**：支付宝、滴滴车主、货拉拉、美团、12306、Keep、悦跑圈的实名 / 人脸 / 位置授权界面，网上找不到可打开的截图或评测原文（09-30 那次对标首启弹窗时同样没找到）。所以「主流做法」只能按通行形态 + 负责人描述来做，没有逐家对过。要补，只能在装了这些 App 的手机上自己截图。

## 落到本项目的形态

| 场景 | 改前 | 改后 |
|---|---|---|
| 首启 | 居中弹窗 + 4 个入口（两个协议、完整收集清单、再听一遍） | 居中弹窗 + 两个协议入口 + 不同意 / 同意 |
| 视力状况、预约前 / 同行态 / 接单位置轨迹、语音下单大模型、行程分享 | 整页逐条告知 + 上下两个 88pt 大按钮 | 居中小弹窗：标题 + 一两句摘要 + 可展开「详细说明」（原文）+ 并排等宽按钮 |
| 志愿者实名（身份证号 + 人脸） | 点提交后弹整页同意 | 提交按钮上方勾选框「我已阅读并同意《身份信息与人脸核验授权》」，默认不勾 |
| 盲人实名 | 整页同意 | 整个功能取消（#767，负责人 11-05 定） |

何时问、问几次（每账号一次）、记在哪都没变；告知原文与 `disclosureVersion` 不变。

- App Store 审核以「同意形态不明确」为由拒审第三方 AI 那条。
