## 一句话

不换骨架，不换品牌色。把头卡之外的颜色和按钮样式收掉，让每屏只剩一个重心。

## 七条规则

1. 颜色三分：大面积只用黑、白、灰；状态色只在头卡；黄色只给主按钮；红色只给求助。
2. 头卡铺到屏幕顶：状态色从状态栏开始，下方圆角收住。依据是 WWDC26 把颜色移进内容层的建议。
3. 按钮四级：黄色实心主按钮 → 中性描边次按钮 → 列表行 → 红色描边求助。蓝色描边、粉底、灰胶囊全部取消。
4. 不用卡中卡：一屏一张头卡，加一组列表。
5. 字号四级：主数字或状态句 / 标题 / 正文 / 副文。副文不低于 `.subheadline`，全部走系统文本样式，不封顶。
6. 圆角三级：头卡和页面级块 28–32、列表组 22、按钮 20。全部用连续圆角，不加阴影。
7. 导航用系统件：返回与右上角操作统一成圆形按钮，不再一端有圆形、一端裸箭头。

## 实施顺序

一个 PR 只做一件事，每步都有真机截图和覆盖 suite。

1. 设计 token：中性描边按钮、圆角、字号、去阴影。回写 `docs/ui/design-direction.md`。
2. 订单页头卡通顶，两端共用 `OrderFlowScaffold`。
3. 盲人首页与语音预约。
4. 志愿者首页与汇合页。
5. 求助中心、角色选择、登录、二级页收尾。

行为不变，只改外观。开工时仍用 `openspec-propose` 记一个视觉变更，把 tasks 列成上面五步。
