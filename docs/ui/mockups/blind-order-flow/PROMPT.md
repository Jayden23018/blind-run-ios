### 工作方式
1. **先读代码再动手。** 汇报：UI 框架（SwiftUI / UIKit）、最低 iOS 版本、项目架构、现有订单状态枚举与流转、现有的首页和各订单状态页面在哪些文件、网络层与 WebSocket 如何推送订单状态、是否已实现「求助与安全中心」（之前的任务里做过）。
2. **先交计划，等我确认再写代码。** 计划包括：
   - 新增和修改的文件列表，以及**要删除的旧页面**
   - 现有订单状态 → 本设计 4 个步骤的映射表（见第 3.1 节）
   - 设计需要但接口里没有的数据清单（见第 5 节）
   - 你发现的与本文档冲突或本文档没考虑到的地方
3. **分阶段实现，每阶段结束后编译、运行、截图对照、跑测试，然后停下汇报：**
   - 阶段 1：设计 Token（颜色、字号、间距、圆角、阴影）+ 通用组件（按钮、卡片、列表行、进度条）
   - 阶段 2：首页
   - 阶段 3：订单页四个状态的静态布局（先不做动画），接入真实状态或 Mock
   - 阶段 4：状态之间的过渡动画 + 首页到订单页的转场
   - 阶段 5：VoiceOver、动态字体、减弱动态效果、触感反馈
4. **对照验收（每个阶段都要做）：** 在 iPhone 16 Pro 模拟器、默认字号、浅色模式下运行，用 `xcrun simctl io booted screenshot` 截取每个状态，与 `screens/` 下的参考图并排比较，**逐项列出差异**（位置、尺寸、颜色、字号、间距），修正后再截图确认。不要只说"已与设计一致"。
5. 做一个仅在 DEBUG 构建中出现的**状态切换器**（例如摇一摇或长按导航标题弹出菜单），可以直接切到四个状态，方便截图和测试。Release 构建中不得出现。
6. 本轮**不做**：志愿者端界面、深色模式、Apple Watch、锁屏实时活动（Live Activity）、求助与安全中心的内部功能（沿用已有实现）。
7. 遇到第 6 节的待决定问题时，停下来问我，不要自行假设。

### 关于"1:1 复刻"的标准
目标是**在默认字号下视觉一致**，而不是像素级相同：参考图用思源黑体渲染，iOS 上用系统苹方，字形会有细微差异，这是正常的。所有字号必须支持动态字体（Dynamic Type），用户调大字号后布局允许变化，但不能截断、重叠或遮挡按钮。**不要为了像素一致而写死字号或禁用动态字体。**

## 1. 为什么这样设计（实现时遇到取舍请回到这里）

1. **一个订单页贯穿全流程，不再每个状态跳一个新页面。** 旧版每个状态是独立页面，切换生硬。更严重的是，iOS 切换页面时 VoiceOver 会把焦点移回页面第一个元素，读屏用户每次都要从头找。单页原地更新可以让焦点保持不动，只播报变化。
2. **页面骨架固定，状态变化只换内容。** 进度条、状态区、信息列表、底部操作区在四个状态下位置都不变，用户靠位置记忆操作。
3. **底部只有两个按钮：一个随状态变化的主按钮 + 固定的「求助与安全」。** 旧版把打电话、修改取消、求助三个按钮并排，重点不清。「修改或取消预约」是低频的破坏性操作，放到信息列表最后一行，固定位置、文案不变、点击后二次确认。
4. **首页最大的位置永远是即将开始的订单。** 视障用户打开 App 第一句听到的就是最重要的信息。
5. **首页只有两块：深蓝的订单卡片 + 浅蓝的预约入口。** 整张卡片是一个可点元素，读出来是一句完整的话，而不是被拆成时间、地点、名字、小按钮好几段。
6. **陪跑员信息只放视障跑者能用上的内容：** 认证状态、陪跑次数、引导绳经验。不放穿着、外貌这类需要看见才有用的信息。
7. **黄色只用在当前最重要的一个按钮上；实心红色只留给求助中心里的「紧急求助」。** 入口按钮用浅红底深红字，醒目但不会让人以为点一下就报警。
8. **跑步中的反馈以声音和触感为主。** 状态变化时自动播报关键节点，并配合不同的触感。

## 3. 界面规格

### 3.1 状态映射
设计中的四个步骤是：**匹配 → 约好 → 出发 → 汇合**。请根据现有订单状态做映射，并在计划中给出映射表。已知旧版界面中存在的状态有：系统派单中、已约好、待出发、志愿者出发中。
- 系统派单中 → 匹配
- 已约好、待出发 → 约好（「待出发」时副标题改为提醒即将开始，例如"还有 15 分钟，请前往集合地点"）
- 志愿者出发中 → 出发
- **汇合**：如果现有状态机没有"陪跑员已到达"这个状态，停下来问我（见第 6 节）

订单进入跑步中后，跳转到已有的跑步中页面，这是唯一允许的页面跳转。

### 3.2 首页（参考 `screens/01-home.png`、`home.html`）
从上到下：
1. 问候「你好，{姓名}」，作为标题（`isHeader`）
2. **深蓝订单卡片**（整张卡片是一个按钮）：
   - 小字：「下一次陪跑，{状态文字}」
   - 大字：时间，例如「明天 7:00」
   - 地点行：定位图标 + 集合地点
   - 分隔线下：陪跑员头像（姓氏）+「陪跑员 {姓名}」+ 经验行「陪跑 {次数} 次，引导绳经验 {年数} 年」；匹配中时显示「正在匹配陪跑员」
   - 底部半透明白底条：「打开订单 >」
   - 卡片内容**跟随订单实时状态更新**，例如出发后显示「张伟 8 分钟后到」
3. **浅蓝预约块**（整块是一个按钮）：蓝色圆形加号 +「预约新的陪跑」+ 副标题「选好时间和地点，系统帮你找陪跑员」+ 右箭头
4. 底部标签栏：首页 / 记录 / 我的（沿用现有标签栏，按设计调整样式）

边界情况：
- 没有待进行的订单：不显示深蓝卡片，预约块移到卡片的位置
- 有多个待进行订单：只显示最近的一个，其余在「记录」中

### 3.3 订单页骨架（四个状态共用，参考 `screens/02` 到 `05`）
从上到下，位置在四个状态下保持不变：
1. 导航栏：返回 +「陪跑订单」
2. **状态卡片**（白色）：
   - 进度条：4 个节点 + 3 条连接线，文字「匹配 / 约好 / 出发 / 汇合」。已完成节点为蓝色实心 + 白色对勾；当前节点为蓝色描边 + 蓝色圆点；未到达节点为灰色描边
   - 分隔线
   - 视觉区（124×124）、状态标题、状态副标题
3. **信息列表卡片**（白色），四行：
   - 陪跑员（两行值：姓名 + 经验）
   - 时间
   - 集合地点（带箭头，可点）
   - 最后一行：操作入口（文案随状态变化，带箭头，点击后二次确认）
4. **底部操作区**：主按钮（可能为空）+「求助与安全」

| | 匹配 | 约好 | 出发 | 汇合 |
|---|---|---|---|---|
| 视觉区 | 雷达，外圈蓝色弧线持续旋转（2.4 秒一圈） | 陪跑员头像 | 头像 + 外圈蓝色进度环 | 头像 + 右下角绿色对勾徽标 |

| 分享实时位置给家人 | 求助与安全中心 |

## 4. 动效规格（数值来自 `prototype.html`）

| 过渡 | 规格 | SwiftUI 实现建议 |
|---|---|---|
| 首页卡片 → 订单页 | 卡片放大展开成订单页 | iOS 18+ 用 `navigationTransition(.zoom(sourceID:in:))` 配合 `matchedTransitionSource`；更低版本降级为标准推入 |
| 进度节点 | 填充色 0.3 秒；当前节点圆点从 0 缩放到 1 | `.animation(.easeOut(duration: 0.3))` |
| 进度连接线 | 从左向右延伸，0.5 秒，曲线 cubic-bezier(.2,.8,.2,1) | `scaleEffect(x:anchor:.leading)` + `.spring(response: 0.5, dampingFraction: 0.9)` |
| 雷达 → 头像 | 雷达淡出并缩到 0.55；头像从 0.55 放大到 1 并淡入；透明度 0.4 秒，缩放 0.5 秒 | 两个视图叠放，按状态切换透明度与缩放；可用 `matchedGeometryEffect` |
| 文字替换（标题、副标题、列表值） | 旧文字 0.18 秒内淡出并上移 10pt；新文字从下方 10pt 处 0.28 秒淡入 | `.transition(.asymmetric(...))` + `.id(text)`，或 `.contentTransition(.opacity)` |
| 倒计时数字 | 数字滚动变化 | `.contentTransition(.numericText())` |
| 进度环 | 进度变化 0.8 秒 | `trim(from:to:)` + 动画 |
| 主按钮出现 / 消失 | 高度、透明度从 0 展开，并从下方 16pt 上移，0.45 秒 | `.transition(.move(edge: .bottom).combined(with: .opacity))` |
| 对勾徽标 | 从 0 弹性放大到 1，带轻微回弹 | `.spring(response: 0.45, dampingFraction: 0.55)` |

**减弱动态效果**：检测 `accessibilityReduceMotion`，开启时所有位移、缩放、旋转一律取消，只保留 0.2 秒的淡入淡出，雷达弧线停止旋转。

**触感反馈**（`sensoryFeedback`，iOS 17+；更低版本用 `UINotificationFeedbackGenerator`）：
- 匹配成功、陪跑员已到达：success
- 陪跑员出发：一次轻触
- 剩 2 分钟：一次中等触感

## 5. 无障碍规格（必须全部实现）

### 5.1 首页
- 问候：标题特征
- 深蓝订单卡片：**合并为一个元素**，按钮特征，标签为完整句子，例如：「下一次陪跑，已约好。明天早上 7 点，深圳湾公园 3 号入口。陪跑员张伟，陪跑过 32 次，有 2 年引导绳经验。」提示「双击打开订单」
- 预约块：一个按钮元素，标签「预约新的陪跑」，提示「选好时间和地点，系统帮你找陪跑员」
- 读屏顺序：问候 → 订单卡片 → 预约块 → 标签栏

### 5.2 订单页
- 进度条：合并为一个元素，例如「进度，第 2 步，共 4 步，已约好」
- 雷达、头像、进度环、对勾：装饰元素，对 VoiceOver 隐藏
- 状态标题 + 副标题：合并为一个元素，这是页面里最重要的元素
- 陪跑员行：合并为一句，例如「陪跑员张伟，已认证，陪跑过 32 次，有 2 年引导绳经验」
- 最后一行操作：按钮特征，点击后弹出确认对话框
- 主按钮和「求助与安全」：沿用已有求助中心的无障碍实现（长按 3 秒直达紧急求助、自定义无障碍动作等）
- 读屏顺序：返回 → 进度 → 状态 → 陪跑员 → 时间 → 集合地点 → 操作入口 → 主按钮 → 求助与安全

### 5.3 状态变化时的播报（关键）
- **不要**在状态变化时发送 `.screenChanged`，那会把焦点移回页面顶部。只更新元素内容，并用 `UIAccessibility.post(notification: .announcement, argument:)` 播报
- **只在以下节点播报**，不要每次数字变化都播报：
  - 匹配成功：「已为你约好陪跑员张伟，他陪跑过 32 次，有 2 年引导绳经验。时间是明天早上 7 点，地点在深圳湾公园 3 号入口。」
  - 陪跑员出发：「张伟已出发，预计 8 分钟到达。」
  - 剩 5 分钟、剩 2 分钟各一次
  - 已到达：「张伟已到达你附近。见面后，轻点开始跑步。」
- 倒计时元素设置 `.updatesFrequently` 特征
- 播报可能被 VoiceOver 正在朗读的内容打断：iOS 17+ 使用高优先级的播报属性；更低版本在播报前适当延迟
- 完整播报文案见 `prototype.html` 中的 `S` 数组

### 5.4 动态字体
在最大无障碍字号（AX5）下检查所有界面：文字可以换行，列表行和按钮高度随之增长，页面可以滚动，底部两个按钮不能遮挡内容。
