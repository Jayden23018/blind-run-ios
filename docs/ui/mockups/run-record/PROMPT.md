# 交接给 Claude Code 的 prompt

先把整个 `run-record-handoff` 文件夹放进仓库，建议路径是 `docs/run-record/`。
如果后端和 iOS 是两个仓库，就放在你启动 Claude Code 的那个目录里，保证两个工程它都能访问到。

---

## 第一条（直接粘贴）

我要给「助盲跑」iOS App 加一个「跑后运动记录」功能。相关材料都在 `docs/run-record/`：

- 完整需求、设计规范、接口建议和验收标准：`HANDOFF.md`
- 交互原型：`prototype.html`。用浏览器打开，左侧可以切换两个角色，也可以打开“读屏预览”。只作参考，不要移植网页代码。
- 示例数据：`sample_*.json`

请按这个顺序来：

1. 完整读完 `HANDOFF.md`。
2. 看 `prototype.html` 里两个角色的页面。能跑浏览器就截图看；不能的话就读 HTML 源码，重点看每个元素的 `data-vo` 属性，那就是 VoiceOver 文案。
3. 执行 `HANDOFF.md` 第 9 节的「第 0 步」：浏览后端和 iOS 两个工程，给我一份实施计划。计划里必须写清楚：
   - 现有架构的关键发现
   - 和文档冲突的地方，以及你准备怎么调整
   - 第 10 节的待确认问题里，哪些你能从代码里找到答案，哪些必须问我
   - 分阶段的任务清单
4. **在我确认计划之前，不要改任何代码。**

硬性要求：

- 服从仓库现有的架构、命名、代码风格和测试风格。
- 中国大陆坐标：存储用 WGS-84，画图前再转成 GCJ-02。先看现有的实时追踪页是怎么处理的，保持一致。
- 视障跑者视图的无障碍要求（第 7 节）是验收标准的一部分，不是锦上添花。
- 每个阶段结束都要跑全部测试，后端现有的测试必须保持通过。同时给我三组截图：浅色模式、深色模式、最大字号。
- 文档没写清楚的地方直接问我，不要自己编。

---

## 确认计划后（按需修改后粘贴）

计划可以。对待确认问题的回答如下：
1. ……
2. ……

从阶段 1 开始。每完成一个阶段就停下来，告诉我做了什么、跑了哪些测试、有哪些没做完，等我说继续再往下做。

---

## 无障碍走查阶段

对照 HANDOFF.md 第 7 节，逐条检查视障跑者页和陪跑员页。每一条都要写清楚：通过还是没通过、怎么验证的、没通过的话怎么修。
另外，把两个页面在 VoiceOver 下从上往下依次会读出的所有内容，按顺序列一张表给我，我要和原型的 `data-vo` 逐条对比。

---

## 觉得界面不像原型时

打开 prototype.html 里的陪跑员页，和你实现的页面截图并排比较，列出至少 5 处视觉差异（地图占屏比例、路线描边和粗细、卡片圆角和间距、数字字号和字重、颜色），然后逐一修正。
