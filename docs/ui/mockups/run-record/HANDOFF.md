## 1. 背景

助盲跑是连接视障跑者和陪跑志愿者（陪跑员，18 岁以上）的 App，由已登记的志愿服务组织运营。

- 后端：Spring Boot，部署在阿里云 ECS，已有 WebSocket 实时 GPS 追踪、紧急求助、志愿者认证，现有约 116 个通过的测试。
- 前端：原生 iOS，基础 UI 已完成。

现在要加的功能：**一次陪跑订单结束后，两位参与者都能查看这次跑步的记录**，体验对标 Keep、Nike Run Club、Strava、Apple 健身。

和这些产品不同的地方：一条记录属于两个人，而其中一个人看不见地图。所以同一条数据，按角色做两种呈现。

## 2. 目标与非目标

**目标**

1. 订单完成后，陪跑员和视障跑者都能在「记录」里打开这次跑步的详情。
2. 陪跑员看到的是主流跑步 App 水准的路线图和数据（地图为主体、配速着色、分段、轨迹回放）。
3. 视障跑者**不看屏幕也能完整了解这次跑步**：语音讲述、声音路线、每公里一句话，全程 VoiceOver 可用。
4. 陪跑员能看到本次志愿服务时长及确认状态。
5. 双方能互相留言（陪跑员文字 → 跑者端朗读；跑者语音 → 陪跑员端播放）。

**非目标（这一版不做）**

- 跑步过程中的实时界面改版（已有，不动）。
- 心率、Apple Watch 数据（现阶段采集不到；数据模型留好扩展字段即可）。
- 社交动态、点赞、排行榜、勋章（和核心需求无关，后续再说）。
- 分享卡片的完整设计（本版只做「分享给家人」的基础图片，见 P1）。
- 路况/障碍标注、路线库（P2，数据结构别把路堵死）。

## 3. 数据：采集、存储、计算

### 3.1 采集（跑步进行中）

| 数据 | 来源 | 备注 |
|---|---|---|
| GPS 轨迹 | 现有 WebSocket 上报的定位点 | 需确认：现在是否**持久化**了完整轨迹，还是只做实时转发（见第 10 节待确认） |
| 步数、步频 | `CMPedometer`（`numberOfSteps`、`currentCadence`） | 每 10 秒随定位一起上报一次，或结束时整段上传 |
| 相对海拔 | `CMAltimeter.relativeAltitude`（气压计） | 用于累计爬升，比 GPS 海拔可靠 |
| 心率 | 暂无 | 字段预留 `heartRate` 可空 |

### 3.2 存储

- 轨迹点：`{t(相对开始秒), lat, lng, alt?, hAcc, speed?}`，**原始坐标一律存 WGS-84**。
- 一条记录挂在订单上（`orderId` 一对一），双方共享同一份数据。
- 位置数据是敏感数据：只有该订单的两位参与者和所属组织的管理员可以读取。

### 3.3 计算（建议放在后端，订单完成时算一次并缓存）

放后端的理由：两个角色看到的数字必须一致；逻辑可以用现有的测试体系覆盖。

1. **清洗**：丢弃 `hAcc > 30m` 的点；相邻点推算速度 > 7 m/s 的视为漂移丢弃；可选做简单平滑。
2. **距离**：清洗后逐点累加大圆距离。
3. **运动时间 / 自动暂停**：速度 < 0.5 m/s 持续 ≥ 10 秒的区间不计入运动时间。
4. **休息点（stops）**：静止 ≥ 30 秒记一次，记录开始时间、时长、所在距离、坐标。地名 P1 再做（逆地理编码），MVP 可为空。
5. **分段（splits）**：每满 1000 米一段，最后不足 1 公里单独一段；每段给出用时、配速、平均步频。标出最快一段。
6. **配速采样（paceSamples）**：每 50 米一个点，用于配速图和地图着色。
7. **累计爬升**：基于气压计相对海拔，忽略 < 1 米的抖动。
8. **与上一次比较**：同一位视障跑者的上一条记录，给出距离差。
9. **志愿服务时长**：从订单的「会合确认」时间到「订单完成」时间，状态沿用组织确认流程（`PENDING / CONFIRMED / REJECTED`）。需确认现有订单模型里有没有这两个时间点。

### 3.4 中国大陆坐标系（重要）

iOS 的 MapKit 在中国大陆使用高德底图，底图坐标是 **GCJ-02**；`CLLocationManager` 拿到的是 **WGS-84**。直接把 WGS-84 的点画成 overlay，路线会整体偏移几百米。

- 存储、距离计算：用 WGS-84 原始值。
- **只在客户端画图前**做 WGS-84 → GCJ-02 转换（仅对中国大陆范围内的点）。
- 如果仓库里已经在用高德 SDK 而不是 MapKit，就按高德的坐标约定处理，并在计划里说明。
- 先检查现有的实时追踪界面是怎么处理的，保持一致。

## 4. 接口（建议，按现有风格调整命名）

```
GET  /api/orders/{orderId}/run-record
     → RunRecordDTO（结构见 sample_run_record.json）
     权限：订单两位参与者 + 组织管理员

GET  /api/me/run-records?month=2026-09
     → 历史列表 + 月度汇总（结构见 sample_history.json）
     根据当前用户角色返回「跑步记录」或「陪跑记录」

POST /api/orders/{orderId}/run-record/messages
     body: { type: "TEXT", text } 或 { type: "VOICE", audioKey, durationSec }
     语音文件先上传到现有文件存储（如阿里云 OSS），这里只传 key

GET  /api/orders/{orderId}/run-record/track?simplified=true
     → 简化后的轨迹（Douglas-Peucker），用于列表缩略图；可选
```

订单完成事件触发记录计算；计算失败时详情页要有明确的状态（见 6.4）。

## 5. 设计规范

### 5.1 颜色

| 名称 | 值 | 用途 |
|---|---|---|
| 盲道黄 | `#F7BE00` | 视障跑者视图的主按钮底色（文字用黑色）、「最快」标签、跑者头像 |
| 陪跑绳橙 | `#FF6A13` | 轨迹回放中两个点之间的连线、志愿时长图标底色 |
| 配速：快 | `#3558F0` | |
| 配速：中 | `#19B3A6` | |
| 配速：慢 | `#F5B100` | |

- **配速着色**：以本次跑步配速的第 5 和第 95 百分位为两端，线性映射到 快→中→慢 三段渐变。故意不用红绿，照顾色弱用户。
- 其余颜色全部用系统语义色（`label`、`secondaryLabel`、`systemGroupedBackground` 等），自动支持深色模式。

### 5.2 字体与尺寸

- 全部使用系统字体，并支持 Dynamic Type。
- 陪跑员页的大距离数字：约 60pt、`.heavy`、等宽数字（`monospacedDigit()`）。
- 视障跑者页的大距离数字：约 72pt。
- 卡片圆角 18；分组列表圆角 14；底部卡片顶部圆角 22。
- 所有可点击区域不小于 44×44pt。

### 5.3 文案规则

- **视障跑者视图里不出现 `6'15"` 这种写法**（读屏读不对），一律写成「6分15秒」。
- 陪跑员视图可以用 `6'15"`，但对应的 VoiceOver 文案仍写成「每公里6分15秒」。
- 文案用口语、主动语态，不加感叹号。具体文案以原型为准。

## 6. 界面

### 6.1 历史列表（两种角色共用结构）

- 大标题：跑步记录（跑者）/ 陪跑记录（陪跑员）。
- 标题下一行是月度汇总：
  - 跑者：「9月跑了 5 次，一共 22.54 公里。」
  - 陪跑员：「9月陪跑 4 次，服务 3 小时 40 分钟。其中和老陈跑了 3 次。」
- 行内容：日期、地点和搭档、公里数。
  - 陪跑员行左侧有路线缩略图（`MKMapSnapshotter` 生成并缓存）。
  - 跑者行不显示缩略图，字号更大。
- 每行的 VoiceOver 读成一句话，例如「9月20日周六，深圳湾公园，和小林，5.21公里」。

### 6.2 陪跑员：跑后详情（参考原型「陪跑员 小林」）

**布局**：全屏地图在底层；上面叠一个 ScrollView，顶部留出约 60% 屏高的透明区域，下面接一张底部卡片。

- 往上滑时，卡片盖住地图，地图以约 0.35 倍的速度视差上移。
- 滑过阈值后，导航栏从圆形毛玻璃按钮变成实色导航栏，并显示标题「和老陈一起跑」。
- 地图延伸到状态栏下面；状态栏颜色跟随地图样式。

**地图**（建议 `MKMapView` 包一层 `UIViewRepresentable`，比 SwiftUI `Map` 更可控）

- 路线：先画一条白色描边的 polyline（约 11pt），再在上面画 `MKGradientPolylineRenderer`（约 6.5pt），颜色按 5.1 节映射。
- 方向箭头：约每 550 米一个小 chevron，方向随路线。
- 公里标记：1、2、3… 白底黑字小圆点。
- 起点和终点：起终点重合时合并为一个标记，加「起终点」标签。
- 休息点：白色胶囊「⏸ 休息 1:40」。
- 视野：让整条路线落在卡片上方的可见区域内，四周留边。
- 样式切换：左上角「标准 / 夜跑」。夜跑用深色地图配置，路线加一层发光效果。
- 不显示用户当前位置；隐藏 POI 或只保留公园、地铁这类地标。

**轨迹回放**

- 用 `CADisplayLink` 驱动，约 9.5 秒走完全程，在休息点停顿约 0.9 秒。
- 已走过的路段正常显示，未走到的路段变淡。
- 两个点（跑者黑点、陪跑员橙点）之间连一条橙色短线，代表陪跑绳。
- 相机跟随并放大约 2.2 倍，结束后回到全局视野。
- 左下角浮层实时显示「x.xx 公里」和当前配速。
- 按钮在「轨迹回放 / 停止」之间切换。
- 开启「减弱动态效果」时不做相机缩放，只移动点。

**底部卡片**（从上到下）

1. 两个叠放头像（陈：黄底；林：黑底）、「和老陈一起跑」、日期时间和地点。
2. 大号距离数字「5.21 公里」。
3. 三列主数据：运动时间、平均配速、步频。三列次要数据：步数、累计爬升、中途休息。
4. 志愿服务行：时钟图标、「志愿服务 45 分钟」、时间段说明、状态标签「待确认」。点击进入时长明细（P1）。
5. **配速图**（Swift Charts）
   - AreaMark 加 LineMark，颜色按配速水平渐变；快在上、慢在下。
   - 平均配速画一条虚线 RuleMark，休息位置加标注。
   - 用 `chartOverlay` 实现拖动：读数显示「距离 / 配速 / 步频」，**同时在地图上移动一个点到对应位置**。
6. **分段列表**：列为 公里、配速、配速条（长度按速度、颜色按配速）、步频。点一行会高亮地图上的这一公里、显示气泡「第3公里 5'58"」，并把页面滚回顶部。
7. **途中记录**：时间轴，包括会合、开始、休息、结束、订单完成。底部注明「全程没有触发紧急求助」，数据来自现有订单和紧急求助记录。
8. **老陈的回复**：语音条，带播放按钮和时长；有转写文字时一并显示。
9. **给老陈留句话**：输入框、三个快捷短语、发送按钮。发送后显示「已发送。老陈打开这条记录时会听到这句话。」

### 6.3 视障跑者：跑后详情（参考原型「视障跑者 老陈」）

**根据 `UIAccessibility.isVoiceOverRunning` 调整页面顺序**（在原型基础上已确认的调整）：

- **VoiceOver 开启**：先听后看，顺序和原型一致，地图放在后面。
- **VoiceOver 关闭**（多数是低视力用户）：在最上方加一张**高对比大地图**。
  - 深色底图，路线用盲道黄 `#F7BE00`，约 9pt，加黑色描边。
  - 不使用配速渐变。
  - 公里标记放大。
  - 其余内容顺序不变。
- 监听 `voiceOverStatusDidChangeNotification`，状态变化时实时切换。

**内容顺序（VoiceOver 开启时）**

1. **头部**合成为**一个**无障碍元素，读作：「9月20日星期六早上，和小林在深圳湾公园跑步。5.21公里，运动时间32分34秒，平均每公里6分15秒，比上次多跑0.41公里。」
2. **听这次跑步**：黄色大按钮，右侧有盲道提示砖一样的圆点纹理，至少 96pt 高。点击后用 `AVSpeechSynthesizer`（zh-CN）读一段讲述，再点一次停止。讲述下方显示文字稿。
   - 讲述由模板和数据生成，示例见原型里的 `NARR` 常量。
   - 包含：时间、搭档、地点、距离、用时、配速、和上次比较、最慢和最快的一公里、休息地点和时长、步频评价，最后读出陪跑员的留言。
3. **用声音走一遍路线**（sonification）
   - 用 `AVAudioEngine` 实现，全程约 26 秒：
     - 每 100 米对应约 0.45 秒。
     - 连续三角波，音高 380–760 Hz，跑得越快音越高。
     - 左右声像跟随路线的东西位置（`AVAudioMixerNode.pan`）。
     - 每到整公里，响 N 声短促的 1250 Hz 提示音，第 N 公里就响 N 声。
     - 到休息点时，声音淡出，响一声低音（约 190 Hz），约 1 秒后再淡入继续。
     - 结束时是两个上行音。
   - 播放时，上方的配速条随进度点亮，屏幕上显示「第 N 公里」。VoiceOver 开启时可用 `UIAccessibility.post(notification: .announcement, argument:)` 播报，但**不要和提示音重叠**；拿不准就只做屏幕文字，不做播报。
   - 音频会话用 `.playback` 并设置 `.duckOthers`。
4. **每一公里**：每行合成为一个元素，读作「第3公里，5分58秒，本次最快，步频每分钟171步。」
5. **小林的留言**：显示文字，下面是「朗读留言」按钮和「回复小林」按钮。回复是录音：点一次开始，再点一次发送（`AVAudioRecorder`，m4a）。
6. **路线**：地图（VoiceOver 开启时放在这里）、一段路线文字描述（由转弯、折返、地标生成，MVP 可以用模板）、「分享给家人」按钮。
7. **更多数据**：步数、平均步频、累计爬升、中途休息、总时长（含休息）。

### 6.4 状态

| 状态 | 表现 |
|---|---|
| 加载中 | 骨架屏；VoiceOver 读「正在加载跑步记录」 |
| 记录生成中（订单刚完成） | 「记录正在生成，大约 1 分钟后可以查看」，并自动刷新 |
| GPS 点太少，无法画路线 | 隐藏地图，数据照常显示，写明「这次没有记录到完整路线」 |
| 没有步频数据 | 隐藏步频相关的列和句子，**不要显示 0** |
| 网络错误 | 说明发生了什么，并提供「重试」按钮 |
| 历史列表为空 | 跑者显示「完成第一次陪跑后，记录会出现在这里」；陪跑员显示对应文案 |

## 7. 无障碍要求（验收时逐条检查）

- [ ] 所有元素的 `accessibilityLabel` 与原型中的 `data-vo` 一致（文案可以润色，信息不能少）。
- [ ] 视障跑者页进入后，往右划**一次**就能到达「听这次跑步」。
- [ ] 没有任何控件被读成单独的「按钮」「图片」。装饰性图形设置为 `accessibilityHidden(true)`。
- [ ] 配速图提供 `AXChartDescriptor`，在转子里可以用 Audio Graph 播放。
- [ ] 陪跑员页地图设置一段整体描述；地图内部的标记不逐个暴露给 VoiceOver。
- [ ] Dynamic Type 调到最大号时，三列数据改为纵向排列，文字不截断。
- [ ] 深色模式、「增强对比度」、「减弱动态效果」都正确响应。
- [ ] 所有颜色表达的信息都有文字或形状作为冗余：配速条有数值，「最快」有文字标签。
- [ ] 语音讲述、声音路线和 VoiceOver 同时发声时不互相打断：开始播放前停止其他音频，VoiceOver 焦点移动时暂停。

## 8. 需求优先级

**P0（MVP 必须有）**

- 后端：轨迹持久化（如果还没有）、记录计算、两个 GET 接口，以及对应单测。
- iOS：历史列表、陪跑员详情（地图、底部卡片、配速图、分段、途中记录）、视障跑者详情（讲述、声音路线、每公里、更多数据）、第 7 节全部无障碍要求。
- 志愿服务时长的展示（只读）。
- 陪跑员文字留言，以及跑者端朗读。

**P1（紧随其后）**

- 跑者语音回复（录音、上传、陪跑员端播放）。
- 轨迹回放、夜跑样式、配速图拖动与地图联动。
- 「分享给家人」：用 `ImageRenderer` 加地图快照，生成一张带文字说明的图片。
- 休息点地名（逆地理编码）。
- 低视力高对比地图（VoiceOver 关闭时显示）。

**P2（现在不做，但数据结构要留好）**

- 心率（Apple Watch / HealthKit）。
- 路况与障碍标注，供下一次陪跑参考。
- 常用路线库。
