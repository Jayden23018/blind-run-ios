# 给 Claude Code 的开场 prompt

把整个 `design_handoff_running_state/` 文件夹放进仓库（或直接附给 Claude Code），然后发下面这段。

---

这是「助盲跑」iOS App（为视障跑者匹配有视力的陪跑员）的设计交接包，实现「汇合之后 → 跑步中 → 跑后」这一段。目标平台是本仓库的原生 SwiftUI 工程。

先读三样东西，顺序不要变：

1. `design_handoff_running_state/README.md` —— 总规格、动效参数、状态机、播报队列规则、完整 token 表，以及**每类东西映射到本仓库哪个现成实现**的表格
2. `design_handoff_running_state/状态清单.md` —— **唯一权威的逐屏规格**。23 个画面，每屏给出界面元素 / VoiceOver 标签 / 播报文案 / 触发条件 / 播报优先级
3. `design_handoff_running_state/screens/*.png` —— 六组画面的 1:1 位图，**像素基准**。A 组前三屏（汇合 / 倒计时 / 跑步中）要做到逐像素一致

硬约束，任何一条都不要自行"优化"：

- **颜色、字号、尺寸、组件一律复用仓库既有实现**：`AppColors.Flow`（FlowPalette.swift）、`FlowMetrics` / `FlowFonts`、`FlowCard` / `FlowStepper` / `FlowAvatar` / `FlowInfoRow` / `FlowActionButton`。**不要新造任何颜色或字号**。README 的映射表里找不到来源的值，就是不该出现的值。
- **跑步中是订单页原地变形，不开新页面。** 跳页会让 VoiceOver 焦点回到顶部。
- **主按钮位置永不变化，只换文字与图标。** 汇合 / 倒计时 / 跑步中三屏里它必须在同一坐标。
- **每屏只有一个黄色主按钮 +「求助与安全」**，通栏、上下排列，不并排。
- **可点区域 ≥64pt**（比 WCAG 的 44pt 更严，理由见 README）。
- **禁止**：地图、暂停按钮、并排按钮、五星评分、锁屏上的结束或求助按钮、非紧急场景使用实心红。实心红全 App 只出现在求助中心的「紧急求助」一处。
- **播报队列要真实实现**：优先级 紧急求助 > 警示 > 对方操作 > 按需播报 > 每公里播报；一次只播一条；按需播报打断排队中的每公里播报；每公里播报排队超过 10 秒丢弃；语音不移动读屏焦点。四种提示音的形式见 README。
- 图标一律用 SF Symbols（README 的 Assets 一节列了对应关系）。HTML 原型里的 SVG 只是占位，**不要移植 SVG 路径**。
- README 的 Fidelity 一节写了两处**刻意偏离原设计稿**的地方（不显示「已认证」、求助按钮描边不用 `#F4C3BE`），都附了算过的对比度。**不要"改回设计稿"。**

落地顺序按 README 最后一节走：先做 A 组三屏的原地变形与主按钮不动，再做播报队列与提示音，然后是 ④⑤ 与陪跑员端长按结束，之后才是异常、锁屏、深色与 AX5。

开工前先只做一件事：读完上面三份材料，列出你打算改动 / 新增哪些文件，以及你在规格里发现的**冲突或缺口**（比如后端没有的字段、仓库里已有但与设计不一致的实现）。等我确认再写代码。
