# Handoff: 助盲跑 · 跑步中与跑后（视障跑者端 + 陪跑员端）

## Overview

为 iOS App「助盲跑」（为视障跑者匹配有视力的陪跑员）设计「汇合之后 → 跑步中 → 跑后」这一段。

核心结论只有一条：**跑步中不是新页面，而是订单页原地变形。** 进度条向上折叠成一行「陪跑中 · 张伟」，信息卡下沉淡出，主体换成里程，返回箭头隐藏 —— 而**主按钮的位置一格不动，只换文字与图标**。跳页会让 VoiceOver 焦点回到屏幕顶部，视障跑者每次都要从头找；原地变形让焦点留在原处，只播报变化。

本包覆盖 23 个画面：跑者端主故事板 5 屏、跑者端异常与求助中心 4 屏、陪跑员端 6 屏、锁屏实时活动 2 屏、深色版 4 屏、最大辅助功能字号 2 屏（缺陷版 + 调整版）。

## Fidelity

**高保真（hifi）。** 颜色、字号、间距、圆角、触达尺寸都是最终值，取自仓库既有的设计系统常量，不是示意。请按像素重建。

两处**刻意偏离原设计稿**（沿用仓库里已有的判断，不要改回去）：

1. **不显示「已认证」。** 设计稿的陪跑员行写「张伟，已认证」，但订单详情契约里没有这个字段（`api_spec.yaml` 0 命中）。无字段却印「已认证」是伪造信任标识 —— 而这恰恰是视障用户决定要不要把自己交给一个陌生人时唯一能依据的东西。已投 handoff 请后端补，补齐前不画。
2. **求助按钮描边用 `#C25A4E`（浅色）/ `#FFB4AB`（深色），不是设计稿的 `#F4C3BE`。** 后者压在自身填充上只有 1.37:1，而填充压页面底是 1.05:1 —— 那圈描边在低视力用户眼里不存在，「求助与安全」就退化成一段悬空的红字、没有按钮形状。

### 跑步中（③）的内容区

- 顶行：小头像 ⌀28（底 #DCE6FB / 字 13/600 #2A5BD7）+ 「陪跑中 · 张伟」15/600，padding 14/18
- 里程：82pt / 600 / 等宽数字 / letter-spacing -2 / 居中 —— **全屏最大字号**；标签「里程（公里）」16/400 #5E6679
- 下方两格：时长、配速各 36pt/600 等宽 + 标签 15/400，中间 1pt 竖分隔线
- 只有这三项数据。信息卡移除，不加心率、卡路里、步频、地图

### 求助中心

单列五项（**不是两列方格**）：人工客服 → 分享位置给家人 → 播报我的位置 → 问一句 → 联系陪跑员（走散时「联系陪跑员」提到第一并改浅红强调）。每项 ≥68pt，1.5pt 描边，圆角 14，标题 17/600 + 副标题 13/400。

> 这里偏离了 `SafetyHubView` 现有的 `LazyVGrid` 两列布局：本轮要求的是「顺序」，两列的阅读顺序是左右跳的，五项也凑不满偶数格。单列让 VoiceOver 遍历顺序与文档写的顺序逐字一致。若工程决定保留两列，请同步更新文档里的顺序表述。

「紧急求助」：**声明在最前（读屏第一站）、视觉贴在最底下**，实心红 #B42318 + 白字 28/700 + 副标题「长按 3 秒直接发出 · 轻点会先确认一次」，≥100pt。
本仓库 2026-08-14 真机实测过四种 `accessibilitySortPriority` 排法**全部无效**，唯一管用的是绘制顺序 = 遍历顺序 ⇒ 用 `ZStack(alignment: .bottom)`，SOS 声明在前、上层内容用 `padding(.bottom, 132)` 让位。

**实心红只出现在这一处。** 全 App 别的地方一律浅红底深红字。

## Interactions & Behavior

### 汇合 → 跑步中（本设计的关键动效）

1. 按下「开始跑步」→ 倒计时 3 拍，每拍 1 秒。头像圆**原位**变品牌蓝实心底 + 白色数字 52pt，每拍数字从 1.25 倍回弹到 1 倍（`spring`，约 260ms）。标题「准备开始」/ 副标题「握好引导绳」。主按钮变浅黄 `#FBE6AE` + 文字「准备中」+ `.disabled()`。
2. 说「开始」时，**约 400ms、缓出曲线**，以下动作同时发生：
   - 进度条向上折叠（高度 → 0，透明度 → 0），「陪跑中 · 张伟」展开（高度 0 → 58）
   - 头像从视觉区中央 ⌀92 缩小移到左上 ⌀28（**同一个视图在动**，不是交叉淡入淡出）
   - 信息卡下沉 20pt 并淡出，高度收到 0
   - 主体卡拉高，里程 0.00 从 80% 放大到 100%
3. 主按钮**位置不动**，只把文字换成「播报当前数据」并换图标。焦点因此不会丢。
4. **「减弱动态效果」打开时**：全部改为 300ms 淡入淡出，不做位移与缩放，**倒计时保留**（它是信息，不是装饰）。

### 结束

只有陪跑员能结束：**长按 2 秒**，环形进度（⌀40，线宽 3）从 0 走到满，按住过程渐强震动，**松手即取消**（环形归零、不播报、无提示）。读屏用户走自定义无障碍动作「结束陪跑」，不必真按住。
例外：陪跑员离线超 5 分钟后，跑者端主按钮变「结束跑步」—— 补上这个漏洞。

第一版**不做暂停**。配速按最近的实际移动计算，运动时间由服务端算出。

### 评价

结束时陪跑员就站在旁边，当面评价得不到真实反馈 ⇒ 评价**延后到首页卡片**，三选项竖排：很好 / 一般 / 有问题，24 小时内有效、不推送通知。选「很好」追问「下次还想约张伟吗？」；选「有问题」可语音说明并直接转人工客服。
**不做五星评分。** 陪跑员只能看到评价汇总，「有问题」永不展示给陪跑员。

## State Management

```swift
enum RunPhase { case metUp, countdown(Int), running, completed }   // 同一页面，原地变形
enum RunnerBanner { case none, scattered, volunteerOffline }        // 跑者端警示条
enum VolunteerBanner { case none, gpsWeak, scattered }              // 陪跑员端横幅
```

| 状态 | 来源 | 转移触发 |
|---|---|---|
| `phase` | 订单状态（`DRIVER_ARRIVED` / `IN_PROGRESS` / `COMPLETED`）+ 本地倒计时 | 任一端按「开始跑步」（先按的生效）；陪跑员长按 2 秒结束 |
| 三项数据 | `GET /api/orders/{id}/track` 的 **`blindStats`**（跑者自己的轨迹，不是 `volunteerStats`）| 跟着既有 5 秒订单轮询走，节流到 10 秒一次，不另起定时器 |
| `RunnerBanner.scattered` | 走散判定（约 50 米持续 30 秒，双方 GPS 正常）| **先只提醒陪跑员**；30 秒无人确认才提醒跑者 |
| `RunnerBanner.volunteerOffline` | 陪跑员离线累计 > 5 分钟 | 满 5 分钟才提示，不做中间提示 |
| 电量 | 跑者手机电量跌破 20% / 10% | 各提醒一次 |
| 每公里 | 累计里程跨过整公里 | 首个样本只定基线（`KilometerMilestoneTracker`）|

阈值（走散 50 米 / 30 秒、离线 5 分钟、GPS 弱 2 分钟）都**需要实测调整**。

### 播报队列（必须真实实现）

优先级 **紧急求助 > 警示 > 对方操作 > 按需播报 > 每公里播报**。

- 一次只播一条，按优先级排队
- 按需播报**打断**排队中的每公里播报
- 每公里播报排队超过 10 秒即**丢弃**
- 音乐只压低不暂停；通话中只保留警示
- **语音不移动读屏焦点**
- 合成语音沿用用户 VoiceOver 的声音与语速设置

提示音：前置音（单声 0.3 秒，每公里与按需播报前）· 注意音（两声短音、无震动，电量）· 警示音（三连音 + 强震，走散 / 离线）· 紧急倒计时音（已有）。

**不播报的情况**：GPS 恢复、网络恢复、变形为总结状态时（结束那句已经说过）。

### 尺寸

圆角 24（订单卡）/ 26（首页卡）/ 17（按钮）/ 14（求助中心格） · 页面左右边距 16 · 进度条 padding 16/20/14、节点 ⌀22、点 ⌀9、线宽 2、列宽 ≥48 · 视觉区 124、头像 ⌀92、徽标 ⌀32、进度环线宽 4 · 信息行 52（展示）/ 64（可点）/ 74（陪跑员两行） · 按钮 ≥64、间距 12 · 求助中心格 ≥68、紧急求助块 ≥100

> **触达下限是 64pt，不是 WCAG 的 44pt。** 视障用户靠手指扫过屏幕找控件，按不中的表现是「点了没反应」。可点信息行因此从设计稿的 52 提到 64（纯展示行保留 52）；判据是「这一行按下去会不会发生事情」，不是「它看起来像不像按钮」。

### 字号（全部走 Dynamic Type，`@ScaledMetric(relativeTo:)`）

状态标题 34/600 等宽 · 状态副标题 16/400 · 里程 82（基准 70）/600 等宽 · 时长配速 36/600 等宽 · 顶行 15/600 · 行标签 15/400 · 行值 16/500 · 陪跑员姓名 16/600 + 经验 13/400 · 进度条 13（当前 600）· 按钮 18/600 · 导航标题 17/600 · 头像姓氏 38/600（小头像 13）

**不封顶 Dynamic Type。** AX4 / AX5 正是低视力用户实际会设的档位，封顶等于把最后两级从目标用户手里拿走。风险转移到布局上，具体调整见 F 组两屏与 `状态清单.md` 第 22–23 条：两格改竖排 + 内容区可滚动 + 按钮高度由内容顶开 + 里程 `minimumScaleFactor(0.7)` + `lineLimit(1)`，而**主按钮距屏底恒为 90pt**。

## 落地顺序建议

1. 先做 A 组 ①②③ 的原地变形与主按钮不动 —— 这是整个设计的地基
2. 再做播报队列与四种提示音（异常播报全部依赖它）
3. 然后 ④⑤ 与陪跑员端长按结束
4. B 组异常与求助中心重排
