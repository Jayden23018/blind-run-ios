## 决定

1. **选方向 C（浅灰底 + 卡片）**。原话：「我自己看我会喜欢最后一版。次选就是方向 B。」对整屏一种颜色（B）的原话：「整个都换成一个颜色。你确定好吗？」B、A 不做。
2. **两屏彩色卡同一个位置、同一个大小；已完成页地图挪到卡片下面**。原话：「跑步中和跑完了……这一个卡要不要同一个位置，跑完了你的那个地图和卡的顺序调换一下，这样显得统一一点」。两屏都是：标题 → 彩色卡 → 其余。
3. **评价用已经做好的那一套，不用「挺好 / 不太好」**。原话：「我记得我不是做了一个图表的，就不是说好和不好，而是有那种评分的星级的就可以了。」仓库里现有的是五档文字 + 跑步小人（很差 / 较差 / 一般 / 顺利 / 很顺利，`RunExperienceRatingPicker`；2026-10-07 定过「不用星星」），契约仍是 1–5 分。**按现有这套放，不新画星星**；负责人若确实要星星外观，另开一项。已完成页当页放。**改 11-07「评价只在跑步详情」**（`order-done-review-20261107/`）。
4. **定稿并实现**。原话：「可以，我觉得就按照这个进行修改吧。然后装到我的手机上。」
5. **彩色卡用定稿图的渐变，不用纯色状态色**（2026-11-12 装机第二轮后）。原话：「你的这一个修订版里面的两个颜色会偏深一点，我这个绿色看的就不好看，但是你这两面的绿色整体就会更加高级、更有质感一点。」陪跑中 `linear-gradient(160deg,#0B4A53 0%,#0F6570 100%)`，已完成 `linear-gradient(160deg,#124F2B 0%,#1B6E3F 100%)`，亮暗同值。白字压最浅一端 6.74 / 6.27。只用于这两屏的彩色卡；`AppColors.Flow.stateRunning` / `stateDone` 别处照旧。代码在 `BlindRunCardsPalette`（`blindRun/BlindRunner/BlindRunCardsComponents.swift`）。
6. **陪跑员卡和评价卡照定稿图的数值收紧，已完成页标准字号一屏看完**（同一轮）。原话：「设为固定搭档这一个，整个占的地方太大了，但是你的设计稿里面是比较紧密的。」「这次陪跑怎么样也是太大了，我的设计稿里应该能一面看完，但是现在的版本它一面看不完。」陪跑员卡一行、高 72；评价五格每格看得见的部分 52 高，可点区仍是 64（多出的落在卡片留白里）；路线小图高 84；没选评价之前不放「选一项就能提交…」那行说明。
7. **陪跑中没有数据的那一刻要有样子**（同一轮）。原话：「陪跑中如果一开始没有数据的话就会显得非常的单调和丑，也考虑一下这个问题。」做法是实现方提的，**负责人还没看过**：① 彩色卡没有里程时不摆三个「--」，同一张卡同一个大小，写「已开跑」和一句「跑出一段路后，这里显示里程、用时和配速。」；② 彩色卡下面加一张「计划跑 N 公里」卡，带一条进度横条（样子照定稿图「每公里」卡的横条），订单没填计划里程就不出现。不编数据、不加地图、不加按钮。没做本地计时：订单上没有开跑时刻，中途重进这一页时本地计时会是错的；后端算好的已用时（`OrderDetailResponse.run.elapsedSeconds`）只在订单刷新时更新、不会走秒，这一轮没接。
8. **开跑后的主按钮用深色胶囊，不用黄色**（2026-11-12 装机第三轮后）。原话：「只要开始了跑步以及订单界面，他的这个完成按钮又全部变成黄色。的应该统一变成我的那一个深黑色吧。订单状态的那种颜色」。盲人订单页出发、已到达、陪跑中、已完成四屏共用一条底栏，四屏一起换成前四屏那枚深色胶囊（`BlindOrderStageButton`，`AppColors.Flow.navy`）。出发、已到达两屏也跟着变，负责人同日看过装机包后确认：「保留」。陪跑员端没动。
