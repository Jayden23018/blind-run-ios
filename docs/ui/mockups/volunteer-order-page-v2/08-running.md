# 08 · 跑步中（v2 新增）

画板：`Run.dc.html`（⑥）、`RunSignal.dc.html`（⑥b）、`RunHelp.dc.html`（⑥c）、`RunStates.dc.html`（其他状态与提示）、`LiveRun.dc.html`（锁屏）。

v1 交付包写的是"跑步中沿用现有实现、不在本期范围"。v2 起跑步中按本文件实现。如果现有代码里已经有跑步中页面（按《跑步中与跑后》规格做的），**不要推倒重写**：先对照本文件列出差异，保留已有的计时、轨迹、结束流程，只改视觉和新增能力。

## 一、设计原则

陪跑员一只手握引导绳、眼睛看路，**屏幕只用来偶尔瞥一眼**。所以：
- 和其他状态一样用浅色页面（系统深色模式整体跟随，不单独做深色页），头卡换成 `stateRunning`
- 屏幕上只有一个超大距离、一条带折返点的进度条、用时和配速
- 页面上**没有黄色主按钮**；黄色只留给李明发来的节奏信号
- 求助在右上角同一位置（`HelpPill`，与其他状态一致）

## 二、⑥ 跑步中 `running(paused: false)`

**NavBar**：左侧空（不放返回，避免跑步中误离开；从系统返回手势进入首页时订单仍在后台继续）·「陪跑中」· 求助

**头卡（`stateRunning`，内边距 20 上 / 24 左右 / 24 下）**
1. 一行：左「陪跑中 · 深圳湾公园」14 bold `onHeroEyebrow`；右侧迷你并肩引导绳（`RopeView(state: .together)`，约 92×40）
2. 「2.40」104 heavy，字距 −5，等宽数字 +「公里」22 bold `onHeroBody`。**距离 ≥10 公里时字号按宽度自动缩小**（`minimumScaleFactor(0.7)`，保证不换行）
3. 进度条：高 10、圆角 5，底 `onHeroTrack`，填充白色。有折返点时在折返位置画 2×22 的 `gold` 竖线
4. 进度条下一行三段文字，14 semibold：左「还剩 2.60 公里」`onHeroBody`；中「2.50 折返」`gold`（无折返点时不显示）；右「目标 5.00」`onHeroBody`
5. 分隔线（`onHeroDivider`，上方 24 间距，下方 16 内边距），下面两列：「18:32 / 用时」「7'43" / 配速 / 公里」，数字 36 heavy

数字精度：距离一律两位小数；配速 `m'ss"`；用时 `mm:ss`，满 1 小时为 `h:mm:ss`。

**节奏卡**（白色，圆角 20，内边距 16）：左侧 40pt 圆（底 `runningTint`，中间 10pt `stateRunning` 圆点）；「李明的节奏」14 `inkSecondary` / 「刚刚好」18 heavy；右侧「2 分钟前」14 `inkSecondary`。
- 信号只有三种，文案固定：**稍慢一点 / 刚刚好 / 可以快一点**
- 从未收到信号：卡片显示「李明还没有发来节奏」，右侧不显示时间
- **过期**：距上次信号超过 5 分钟，圆点变灰（`#9AA1B0`），标签改为「上次反馈」，文字改为 `inkSecondary`

**耳机语音播报**：整行是一个 `Toggle`（高 64，白色卡片，圆角 20），左侧喇叭图标，「耳机语音播报」15 bold +「每 1 公里，以及李明的节奏信号」13 `inkSecondary`。按 v3 默认关闭，状态记在本地设置里跨订单保留。开启后：每满 1 公里播报「1 公里，用时 7 分 43 秒」；收到节奏信号时播报「李明说：稍慢一点」。使用 `AVSpeechSynthesizer`，音频会话 `.playback` + `.duckOthers`。

**结束按钮**：高 64，圆角 17，白底，1.5pt `borderNeutral` 描边，17 heavy `ink`，左侧时钟图标 +「长按 2 秒，结束陪跑」。
- 按下后从左向右以 `yellow` 填充，2 秒填满；按住期间每 0.5 秒 `.light` 触感；描边变 `yellowBorder`；文案变为「继续按住，还剩 N 秒」
- 松手即取消，填充 0.2 秒回退
- 满 2 秒：`.success` 触感，调用结束接口，页面原地切到 ⑤ 完成（头卡青绿 → 完成绿）
- VoiceOver：朗读「结束陪跑，按钮」，**双击后弹出确认框**「结束这次陪跑？」（结束 / 继续跑），不要求长按

**读屏顺序**：陪跑中，和李明并肩 → 2.40 公里，还剩 2.60 公里，2.50 公里处折返，目标 5 公里 → 用时 18 分 32 秒，配速每公里 7 分 43 秒 → 李明的节奏：刚刚好，2 分钟前 → 耳机语音播报，关 → 结束陪跑。距离数字**不**用 live region 连续朗读。

## 三、⑥b 收到节奏信号

画板：`RunSignal.dc.html`

- 节奏卡**原地**变成信号卡：底 `yellow`，1.5pt `yellowBorder` 描边，阴影同主按钮；左侧 48pt 圆（黑色 10% 底）+ 方向图标（稍慢一点 ↓、可以快一点 ↑、刚刚好 ✓）；「李明：稍慢一点」22 heavy `onYellow`；「刚刚 · 已震动两下提醒你」14 semibold
- **不另外弹横幅**，同一时刻这个信号只在一处出现
- 到达时：两次 `.medium` 触感，间隔 0.15 秒；VoiceOver 用 `announcement` 播报一次；语音播报开启时朗读
- 保持 8 秒后恢复为普通节奏卡（变形动画，见第六节），节奏卡上的文字变成这个新信号
- "刚刚好"不需要打扰陪跑员：只更新节奏卡，不变黄、只震一次

## 四、⑥c 求助面板

画板：`RunHelp.dc.html`。点右上角「求助」打开（其他状态点「求助」进入现有的紧急求助流程；跑步中换成这个面板）。

- 底部面板：白底，顶圆角 24，内边距 8 / 24 / 34；背景遮罩 `ink` 45%
- 标题「需要帮助？」24 heavy；副标题「打开这里不会暂停计时」15 `inkSecondary`
- 三行（每行高 72，可点）：
  1. 暂停图标「李明需要停下来」/「暂停计时，并通知组织值班人员」→ 进入暂停中
  2. 放大镜「我们走散了」/「让李明的手机响起来」→ 调用 05 里的响铃接口（v2 允许在 RUNNING 状态调用）
  3. 电话「联系组织值班人员」/「志愿服务组织值班电话」→ 拨打组织配置的值班号码
- **紧急求助按钮**：`<button>`，高 72，圆角 20，底 `helpInk`（#B42318），白字；左侧 36pt 环形图标内写 SOS；「长按 3 秒，紧急求助」18 heavy +「把位置发给组织和李明的紧急联系人」13。按住时底色加深到 `#8E1B12`，环形从 0 填满用 3 秒，文案变为「继续按住，还剩 N 秒」；松手取消。满 3 秒调用现有紧急求助能力
- VoiceOver：双击后弹出确认框「发出紧急求助？」（发出 / 取消）
- 底部文字按钮「没事了，继续跑」关闭面板

## 五、其他状态与提示（画板：`RunStates.dc.html`）

**暂停中** `running(paused: true)`：头卡底色过渡到 `statePaused`，小标题「已暂停 · 计时停在 18:32」，距离数字保持；副文「组织值班人员已收到通知」。此时出现黄色主按钮「继续陪跑」（本屏唯一一个），结束按钮保持在它下面。志愿时长只算未暂停的时间。

**提示条**：插在头卡和节奏卡之间，同一时刻只显示优先级最高的一条，出现与消失都是高度动画 0.25 秒。
| 优先级 | 条件 | 样式 | 文案 | 操作 |
|---|---|---|---|---|
| 1 | 疑似走散：两人距离 > 20 米持续 15 秒（两端定位精度都 ≤20 米时才判断） | 底 `helpBg`，字 `helpInk` | 你和李明好像走散了 / 手机显示你们相距约 30 米。先确认他在身边。 | 白色按钮「让李明的手机响起来」 |
| 2 | 跑者电量 ≤20%（v3） | 底 `warmCard`，字 `warmCardTitle` | 李明的手机电量 18% / 跑完记得提醒他充电。 | 无 |
| 3 | 陪跑员自己定位精度 > 50 米持续 20 秒 | 底 `#EEF0F4`，字 `#3F4553` | 定位信号弱 / 距离暂时按步数估算，信号恢复后会校正。 | 无 |

疑似走散时额外 `.warning` 触感一次，语音播报开启时朗读。

**超过目标距离**：进度条填满白色，末端出现 24pt `gold` 圆 + 黑色对勾；进度条下文字改为「已完成 5.00 公里目标 · 多跑了 0.32」，不再显示剩余和折返。跨过目标那一刻 `.success` 触感一次。

## 六、动画

| 触发 | 动画 | 时长 |
|---|---|---|
| 汇合 → 跑步中 | 见 03；头卡琥珀 → 青绿，并肩引导绳缩小飞到头卡右上角 | 0.7 秒 |
| 距离数字变化 | `contentTransition(.numericText())`，每 0.01 公里更新 | — |
| 进度条推进 | 宽度 `.linear(duration: 1)` | — |
| 节奏卡 → 信号卡 | 背景色与描边 0.25 秒过渡，卡片高度 spring 展开，图标缩放 0.8→1 | 0.35 秒 |
| 信号卡 → 节奏卡 | 反向，8 秒后自动 | 0.35 秒 |
| 结束 / 紧急求助长按填充 | 线性填充（2 秒 / 3 秒），松手 0.2 秒回退 | — |
| 暂停 / 继续 | 头卡颜色过渡 0.35 秒；"继续陪跑"主按钮从底部淡入上移 12pt | 0.35 秒 |
| 提示条出现 / 消失 | 高度 0 ↔ 自适应，easeInOut | 0.25 秒 |

减弱动态效果：只保留颜色过渡和淡入淡出；长按填充仍然显示（它是进度信息）。

## 七、后端与接口（补充 05、06）

**节奏信号（新增，跑者端发起）**
- 跑者端：`POST /api/runner/orders/{id}/rhythm` `{ "signal": "SLOWER" | "OK" | "FASTER" }`，仅 RUNNING 状态；同一信号 10 秒内重复返回 429
- 陪跑员端 WebSocket 事件：`run.rhythm { "signal", "at" }`；App 不在前台时发时间敏感推送「李明：稍慢一点」（锁屏只写"李先生"）
- `OrderView.run.lastSignal` / `lastSignalAt` 在 view 接口里返回，冷启动后能恢复
- 跑者端需要实现：跑步中屏幕上三个大按钮或音量键映射（交给跑者端设计），发送成功后 TTS「已告诉张伟：稍慢一点」

**暂停 / 继续（新增）**
- `POST /api/volunteer/orders/{id}/pause`：RUNNING 且未暂停；同时通知组织值班（复用现有紧急响应的通知通道，级别为"提醒"而非"紧急"）
- `POST /api/volunteer/orders/{id}/resume`
- 服务端记录暂停区间，**志愿时长 = 跑步总时长 − 暂停时长**，按 0.1 小时取整；跑步记录的配速也扣除暂停
- WebSocket：`run.paused` / `run.resumed`，跑者端 TTS 播报

**紧急求助**：复用现有 emergency response 能力，只需要确认它接受 RUNNING 状态的订单、并带上双方最新位置。如果现有接口不满足，列入差异表，不要另起一套。

**响铃**：05 里的 `ring-runner` 允许的状态从 `ARRIVED` 扩大到 `ARRIVED | RUNNING`，限流规则不变。

**疑似走散**：服务端在收到任一方位置时计算两人距离；满足条件（见第五节）时发 `run.separation { "distanceM" }`，恢复到 ≤10 米时发 `run.separation_cleared`。客户端只负责展示，不自行判断，避免两端结论不一致。

**跑者电量**：跑者端每 60 秒随位置上报 `batteryLevel`；≤20% 时服务端发一次 `run.runner_battery_low { "level" }`，同一订单只发一次。

**折返点**：订单新增 `route.turnaroundKm`（可空）。路线是往返时，由组织在后台集合点配置里标记"往返"，服务端按 `targetKm / 2` 填写；非往返为 null。

**OrderView 新增**（RUNNING 时非空）：

```json
"run": {
  "startedAt": "2026-09-19T07:02:00+08:00",
  "distanceKm": 2.40,
  "elapsedSeconds": 1112,
  "pausedSeconds": 0,
  "paused": false,
  "paceSecondsPerKm": 463,
  "targetKm": 5.00,
  "turnaroundKm": 2.50,
  "lastSignal": "OK",
  "lastSignalAt": "2026-09-19T07:19:10+08:00",
  "separation": null,
  "runnerBatteryLow": false
}
```

距离和用时以服务端为准（与 v3"时长以服务端开始、结束时间为准"一致），客户端在两次推送之间可以本地插值显示，收到服务端值后校正。
