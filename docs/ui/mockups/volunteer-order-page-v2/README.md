## 用 v2 核对已有实现（第一版已经做过时，用这一段）

后端和前端分别在各自仓库里运行，交付包放在两个仓库的父目录（`../handoff`），和 v1 相同。把旧的 `handoff/` 整个替换成本包。

**第一步：只审计，不改代码。**

```
交付包已从 v1 更新到 v2。读 handoff/README.md 和 handoff/CHANGELOG-v1-to-v2.md，再读 CHANGELOG 里每一项指向的文档章节。
然后对照当前代码，逐项给出审计表：编号 | 状态（已符合 v2 / v1 已实现但需改为 v2 / 部分实现 / 未实现 / 不适用于本仓库）| 证据（文件:行号）| 改动估计（小/中/大）。
另外单独列出：v1 本来要求、但代码里没有实现的项（对照 07-acceptance.md 前半部分）；以及代码里存在、但 v1 和 v2 文档都没有要求的改动。
不要修改任何文件。审计表写到 handoff-audit-<仓库名>.md。
```

**第二步：确认审计表后再改。**

```
按 handoff-audit-<仓库名>.md 里我确认过的项实现 v2。顺序：先 CHANGELOG A 类（设计常量和组件，一次改完），再 B / C 类。
每完成一组，更新审计表里的状态，并跑一遍 07-acceptance.md 与 08-running.md 第八节中相关的检查。现有测试必须保持通过。
```

画板源码在 `reference/artboards/`，v2 新增了 `Run`、`RunSignal`、`RunHelp`、`RunStates`、`LiveRun`，`Rope` 改成了"状态色与引导绳"。

## 给 Claude Code 的开场指令（从零开始时）

先让它读现有代码，再动手。现有项目：iOS 原生（已有基础 UI），后端 Spring Boot（已有 WebSocket GPS 追踪、紧急求助、志愿者认证，部署在阿里云 ECS）。本包里的类名、接口路径、字段名都是**建议**，和现有代码冲突时以现有代码为准，并在 PR 说明里写清楚映射关系。

**后端（先做，前端依赖它）：**

```
读 handoff/README.md、00-decisions.md、05-backend.md、06-api-contract.md、07-acceptance.md。
先梳理现有代码里的订单状态机、订单实体、推送和 WebSocket 实现，输出一份"现有 vs 本包"的差异表给我确认，不要直接改。
确认后按 05 和 06 实现，每个新增能力都要有单元测试，现有 116 个测试必须保持通过。
```

**前端 iOS：**

```
读 handoff/README.md、00 到 04、06、07。
先梳理现有 SwiftUI 工程里订单页、设计常量、网络层的结构，给我一份改造计划，不要直接改。
确认后：先实现 01 里的 DesignTokens 和通用组件（附 SwiftUI Preview），再实现 RopeView 及其动画，最后按 02 逐个状态接入订单页。
后端接口未就绪时用 06 里的 DTO 写 mock，所有状态都要有 Preview。
```
