① 颜色：通话这一步不再加颜色

v6 给通话前、通话后各配了一种新颜色（紫、梅红），加上匹配灰蓝，一共 8 种头卡色。本稿把通话归回进度绳的第一格「匹配 / 邀请」，整步沿用同一种颜色；通话前、等安排、听安排这几个子状态靠头卡那句话和绳子上的小图标区分（电话 → 单子），不靠换色。颜色只是冗余线索，状态由那句话承担（design-direction.md §2）。

⑤ 两端时间线：谁在什么时候看到、听到什么

中间一列是系统真正知道的事。界面只说这一列里有的事 —— 例如系统不知道电话接通没有，所以两端都不说「通话中」。

#盲人端系统知道什么陪跑员端
1B1 弹出，播 「有一位志愿者想陪您跑步……」（后端 INTRO_CALL_READY）陪跑员点了「有意向」，20 分钟窗口开始V1「等王*打电话给你」
2点「打电话给李*」→ 系统拨号确认框 → 进入系统电话盲人按了拨号（notify-incoming，客户端 60 秒内最多发一次）V1′ 播 「王*正在给你打电话，请接听」，持续 2 分钟
3（在系统电话里，App 不显示）不知道接通没有、聊了多久（在接电话）
4挂断回到 App → B2「等李*发来见面安排」只知道 App 从后台回到了前台点「聊过了，填见面安排」→ V2
5B3 自动出现，焦点落标题，播 「李*发来了见面安排，改了 2 项」收到安排单第 1 版；校验通过（提前量、7 天、时长、夜间、3 公里、时段）V3，播 「已发给王*确认」
5a点「不对，再打电话说」→ 直接拨号又一次 notify-incoming；安排单保留再次 V1′ 来电提醒 —— 不告诉他「跑者不同意」
5b（若在听）焦点回标题，播 「李*改了安排，请再听一遍」安排单第 2 版，盲人之前的确认作废点「修改安排」重新提交
6安排单发来 10 分钟未确认 → 提醒一次（播报 + 本地通知）安排单版本与盲人确认状态不提醒，不显示跑者状态
7剩 5 分钟、剩 1 分钟各播一次，内容按当前屏说下一步windowEndsAt同样两次，「还剩 5 分钟」

8′超时 / 换一位 → 「这次安排没有生效。正在为你寻找……」本轮结束，安排单删除V4′ 没约成（同一句，不说原因）

请负责人确认的视觉决定

1. 颜色　通话整步沿用「匹配 / 邀请」灰蓝，去掉 v6 的紫和梅红（头卡色 8 → 6）。⚠️ 灰蓝本身来自在途 PR #399；若 #399 最终不用灰蓝，通话步骤跟随匹配页（main 上盲人端匹配页是白卡）。
2. 子状态怎么区分　靠头卡那句话 + 绳子第一段上的小图标：电话（等通话）→ 灰色单子（等安排）→ 不画绳子、改成大标题「见面安排，改了 N 项」（听安排）。
3. B3 的两个大按钮　「对，就这样」黄、「不对，再打电话说」白底蓝框，同样 84pt 高。
4. 「改了」标记　浅蓝小标签 + 下面一行「原来 …」。不用删除线（读屏念不出删除线）。
5. 上衣颜色　陪跑员表单里用色块（内容颜色，不是界面装饰色）；盲人端只出现颜色名。

不变的规则

不显示对方的表态 · 不显示第几位志愿者 · 陪跑员端号码只显示打码版本、不能回拨 · 「一直没接到电话」与「不合适」仍是两个动作 · 没约成不说原因 · 改约后由盲人确认才生效。
