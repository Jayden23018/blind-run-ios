状态：**待负责人定**（v3 稿）。依据 `docs/research/live-activity-design-20261111.md`，参考来源见 `REFERENCES.md`。

## 负责人已定（2026-11-11）

1. 盲人端、陪跑员端都做；陪跑员现有出发 / 汇合卡、跑步卡一并按新语言重画。
2. 开跑前 30 分钟起实时活动；开跑前 1 小时本地出门提醒不变（`blind-order-tracking-20261109/DECISION.md` 第 10 条不推翻）。
3. 卡分两段。原话：「只要匹配中着一个状态开着即可，然后匹配到人就进入下一个阶段，直到这个约好然后等待开始的时间就不需要了」。第一段 匹配中 → 商量见面安排 → 已约好（收卡）；已约好到开跑前 30 分钟不出卡；第二段 30 分钟起 → 出发 → 已到达 → 陪跑中 → 完成。
4. 本轮只交调研 + 设计稿，定稿后另开实现。
5. v1 稿被否：负责人原话「现在这个排版很拥挤，非常不好看」，并指出没先看好的参考再动手。v2 照 Uber / Uber Eats / DoorDash / 美团 / Flighty 的共同版式重排（三层 + 右侧圆头像 + 底部至多一个进度图形，只强调一个数字）。

6. 看 v2 后（11-11）原话：「还是太拥挤了，一个底部横条可以要，匹配中和找人的订单状态可以多参考uber来做，跑步中多参考健身类型的来做」。⇒ v3：底部留一根横线（原待定项 A 关闭）；找人与赶路照 Uber（一根细线 + 标记沿线走、终点空心圆，组间距照 Uber 量的比例，标准卡 145pt ≈ Uber 143pt）；跑步照 Gentler Streak / Apple 健身（三个并排大数字 + 彩色小标签 + 右侧圆键）。
7. 卡上不写名字。原话：「我觉得也不需要说是谁来了，就是说这个陪跑员正在赶来就可以」。⇒ 标题写「陪跑员正在赶来」「陪跑员到了」，右侧用通用人像；陪跑员端同理写「跑者」。

8. 看 v3 后（11-11）说「差不多」，只改底部横线：原话「可不可以把我给你的那一个就是原本竖着的那个排版在横着的上面的。这里标在一些节点呢…我希望它不同的节点可以代表不同的东西…一个是显示当前的进度，然后另一个是当陪跑员来的时候显示陪跑员离自己还有多远的一个距离」。⇒ 进度线两种显示：**看步骤**（匹配中 → 开跑前 30 分钟，五个节点 = v7 五步：匹配 / 商量 / 出发 / 汇合 / 开跑，当前一步加粗带外圈）；**看距离**（陪跑员出发 → 到达，同一根线放大成「出发 → 你 · 南门」，跑步小人按剩余距离走向你）。陪跑员按出发时切换，约 1 秒放大动画。开跑后照旧是里程 / 目标里程。
