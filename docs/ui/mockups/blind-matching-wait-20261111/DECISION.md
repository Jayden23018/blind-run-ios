# 盲人订单页 · 匹配中的等待与「找到了」那一刻 · 决定记录（2026-11-11 定稿）

issue #909。负责人 11-11 问匹配界面要不要单独做动画，看完调研 `docs/research/matching-wait-screen-20261111.md` 后说「按这个方向出稿」。

版式就是订单页定稿 v7 ①（`blind-order-tracking-20261109/draft.html`），本包只定等待内容和动效。

## 决定（负责人 2026-11-11 原话「可以定稿」，五条全采纳）

1. **不做循环播放的整屏动画**。匹配是长等待（后端 `dispatchDeadline` 对 `PENDING_MATCH` 取开跑前 30 分钟），NN/g 说循环动画不适合超过 10 秒的等待。
2. **深色卡改文案**：「找到后 / 陪跑员会先给你打电话」→「可以先离开这个页面 / 找到后马上通知你」，下半加「最晚开跑前半小时会有结果」。
   - 原句与流程不符：要通话的单是盲人打给陪跑员（推送 `INTRO_CALL_READY`），`requiresIntroCall=false` 的单不通话。
   - 「最晚开跑前半小时」只说规则，不算具体钟点；**要后端确认能这样对用户承诺**。`REMATCHING` 死线规则不同，不显示这一行。
3. **当前圆点呼吸**：外圈 3pt ↔ 11pt，3 秒一个来回；「已等 N 分钟」每分钟刷新，超过 1 小时写「已等 X 小时 Y 分钟」。减弱动态效果时外圈固定 6pt。圆点不进读屏树；等待期间不放循环声音。
4. **找到那一刻约 1 秒**：圆点打勾放大回弹 → 竖线往下长、标题交叉淡入 → 定格在 v7 ②（不用通话的单定格在 v7 ④）。同时震动一次（沿用现有 `RunOrderStatus.haptic`，不新增）、播报一句（现有 B1 原文；读屏开着交给读屏）。减弱动态效果时改成 0.25 秒淡入淡出。
5. **不在页面上**：靠后端已有 HIGH 推送，客户端不改文案；点通知进来直接显示定格后的屏，不补放动画。
