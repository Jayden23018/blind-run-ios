## Why

负责人 2026-11-05 真机体验后反馈：同意条款「每做一步就需要同意一次」，是过度防御；展示形式和主流 App 不一样，主流是「一个小弹窗」或「最底下勾选是否同意」（Jayden23018/blind-run-ios#769）。调研（`docs/research/consent-forms-mainstream-20261105.md`）结论：法规与国标要求先告知、明示同意、不默认勾选、不打包、拒绝后不频繁再问，没有要求整页逐条告知。

## What Changes

- 敏感项的单独同意（视力状况、预约前位置轨迹、同行态位置轨迹、志愿者接单位置轨迹、语音下单第三方大模型、行程分享）由整页逐条告知改成居中小弹窗：标题 + 一两句摘要 + 可展开的「详细说明」（原逐条告知原文）+ 左「不同意」右「同意」两个等宽按钮。何时问、问几次、记在哪不变。
- 志愿者实名（身份证号 + 人脸）由提交后弹整页同意，改成提交按钮上方的勾选框「我已阅读并同意《身份信息与人脸核验授权》」，默认不勾；没勾就点提交，当场显示并朗读要勾哪一项，不发请求。
- 首启弹窗只留《隐私政策》《用户协议》两个链接，去掉「完整收集清单」「再听一遍」一行。

## Capabilities

### New Capabilities

- `consent-forms`: 单独同意的界面形态（小弹窗 / 表单勾选框 / 首启弹窗的入口）。

### Modified Capabilities

- `voice-order-third-party-llm-consent`: 同意界面由全屏页改成小弹窗。

## Impact

- `ConsentDisclosureView` 一处改形态，六个调用方随之变成小弹窗；`PrivacyConsent+Popup.swift` 新增摘要文案；志愿者注册底栏加勾选框。
- 告知原文 `disclosures` 与 `disclosureVersion` 不变，老用户的同意记录照常有效。
- UI 测试里志愿者实名的同意步骤由「提交后点同意」改成「提交前勾选」。
