## Why

项目负责人给了 HTML 原型「星火同行」：一张以城市为范围的夜空地图，志愿者是金色四角星，
视障跑者是带光环的圆点，底部一句「身边有多少人在线」的语音摘要。它的目的是**激励和陪伴感**：
志愿者能看到有多少盲人需要帮助、有多少人和自己在做同一件事；盲人打开就知道身边有人愿意帮忙。

它**替代**此前的「一束光地图」（全国范围、夜光卫星底图，PR #174 关闭）。
调研与差距核对见 `docs/research/xinghuo-companion-map-20260923.md`。

## What Changes

**一期（本变更，纯 iOS）**

- 两端各加第 4 个标签页「星火」（首页之后），**只在调试版编译**。
  城市级聚合数据后端一个都没有（契约 `nearby` / `aggregat` / `/stats` 0 命中），
  一期页面用 App 内置演示数据，正式版不出现这一页。
- 页面：顶部四个数（志愿者在线 / 视障跑者 / 正在同行 / 今日公里）、地图上的聚合片区、
  一句摘要（也是「听见星光」按钮念的内容）、「今日足迹」开关。
- **今日足迹是唯一的真实数据**：自己今天已完成订单的路线（`myOrders` + `orders/{id}/track`）。
- 全 App 的地图改为**跟随系统明暗**（高德 `standardNight` / `standard`），配色只用 `AppColors`。

**不在本变更**

- 二期：后端聚合端点（形状见 spec），接上后去掉调试闸、正式上线。
- 声音化（每位志愿者一个音、左右声道表方向）：只在戴耳机时启用，另起变更。
- 摘要里的方位（「东边」还是「右前方」）：未定，二期再议。
- 志愿者之间互相联系、约跑：单独立项（需要后端、隐私、防骚扰与举报）。
- 订单页不加地图：订单页对盲人没用，志愿者在订单页只关心自己那一单（项目负责人 2026-09-23）。
- 即时叫人陪跑：保持预约制（≥30 分钟 + 通话磨合），AGENTS §5 不变。

## Impact

- 代码：`blindRun/Map/AMapContainer.swift`（共用组件，影响全部地图）、新增 `blindRun/Xinghuo/`、
  两端 TabView、`blindRunTests/XinghuoSnapshotTests.swift`、`AccessibilityAuditTests` 两条 tab 用例 + 一条星火页审计。
- 契约：一期无；二期需要后端新增聚合端点，需求已写进 `demo/docs/handoff.md` 待后端确认。
- 隐私：页面只画**片区**（网格中心 + 人数），从不画个人坐标；动态只给汇总、不带地点、不实时
  （09-13 调研：逐条实时点亮是时序攻击通道）。
