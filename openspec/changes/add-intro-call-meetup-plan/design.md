## Decisions

1. **本地类型与解码分开。** 安排单先用 `Date` / `Double` 等已解析好的值建模，不实现 `Decodable`。备选是先按设计文档猜字段名写 `Decodable`，但契约一改就要连测试一起返工；分开后 #432 只加一个映射。
2. **颜色是开放枚举，未知值降级为 `.unknown`。** 与 `RunOrderStatus.unknown` 同一条红线。「不确定」不是一种颜色，用 `nil` 表示。原始取值暂用大写英文（`RED` 等）作占位，#432 按契约对齐 —— 核对结果：契约十个值与占位逐字相同，`rawValue` 表未改。
3. **回前台判据是一个记住「进过后台」的小状态机，不是相邻两个阶段的比较。** 仓库调研 `docs/research/intro-call-post-call-coordination-20261015.md:70` 记录打完电话回来的真实顺序是 `background → inactive → active`。只比较相邻两个阶段 `(old, new) == (.background, .active)` 在真机上永远不成立。状态机的规则：看到 `.background` 就记一笔；看到 `.active` 时，有这笔记录才返回 true，并清掉记录。`(.inactive → .active)` 没有进过后台，返回 false。
4. **朗读文本一项一个字符串，顺序由函数固定。** 视图按数组渲染成独立读屏元素，顺序不靠视图里的声明顺序（iOS 26 / 27 的遍历顺序规则不同，见记忆 `swiftui-traversal-order-follows-paint-order`）。
5. **变更地点念全名，不省略共同前缀。** 视觉稿示例念「由朝阳公园南门改为东门」，那是人工缩写。按字符截共同前缀会把「朝阳门 → 朝阳公园」念成「改为公园」。集合点由可能是威胁来源的一方改动，念全名更安全。
6. **距离用 `CLLocation.distance(from:)` 计算，显示复用 `DistanceCalculator.formattedDistance`。** 两点都是后端下发的 GCJ-02，同一坐标系内直接算，不再转换。不调 `DistanceCalculator.distance`：工程默认 MainActor 隔离，`nonisolated` 的安排单类型里调不了它。`formattedDistance` 最小报 10 米，所以不到 10 米不念距离。同名不同点念「仍为 X，距原地点约 N 米」，不念「由 X 改为 X」。
7. **倒计时播报节点按「越过阈值」触发，每个节点每个窗口一次。** 第一次观察时就已低于 5 分钟（例如剩 3 分钟才进页面）也触发 5 分钟节点，但念实际剩余分钟数，不念「5 分钟」。直接跳到 1 分钟以内时只触发 1 分钟节点，5 分钟节点同时作废。窗口已过（剩余 ≤ 0）不触发：超时由服务端宣布，客户端不抢先说。窗口结束时刻变化（新一轮）时清零。
8. **常驻那一行向下取整，主动播报向上取整。** 常驻行「剩余 5 分钟」在剩 5 分 59 秒到 5 分整之间显示，不多报剩余时间；不足 1 分钟显示「剩余不到 1 分钟」，包括已过期但服务端还没转走的那几秒。播报在越过阈值后的第一次轮询触发，那时剩 295–300 秒，向下取整会念成「剩余 4 分钟」，所以播报向上取整。
9. **只改结束时间单独成句。** 开始、结束合在一起比较会念出「由 7 点改为 7 点」，所以变更检测分开记开始与结束，只改结束时念「X 开始，结束时间由 A 改为 B」。
10. **数字与汉字之间的空格只加在模板拼接处。** 视觉稿原话是「改为 7 点 30，8 点 30 结束」；地址、见面位置是用户填的，原样念。

## Risks / Trade-offs

- [视觉稿只给了 B3 与陪跑员端的倒计时播报句] → B1 / B2 先念「剩余 N 分钟。」，#434 实现盲人端时如需按子状态补「下一步」，改纯函数并补用例。
- [「无变更」时的 B3 标题视觉稿没画] → 先用「陪跑员<称呼>已提交见面安排，无变更。」，PR 描述里请负责人确认。
- [「先报总数，再逐项」没有针对读屏用户的研究支撑] → 设计文档第 3 节已标为推断，#434 真机找盲人用户试。
- [颜色原始取值是占位] → #432 对齐契约时只改枚举的 `rawValue` 表，测试按枚举 case 写，不受影响。（#432 已核：无需改。）
