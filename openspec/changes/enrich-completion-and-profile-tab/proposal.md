## Why

2026-10-05 两端全流程真机截图交给零上下文评审打分（美观 / 易用 / 吸引力，1–10）：盲人端 6.2 / 6.2 / 4.8，志愿者端 6.6 / 6.7 / 5.5。
吸引力最低的几屏里，负责人当日拍板改四处（其余与既有决定冲突的不动）：

- 陪跑员「陪跑完成」页：吸引力 3/10，绿卡下面 60% 空白。对无偿志愿者，这是最该给认可的一屏。
- 陪跑员「服务成就」页：全是灰卡和文字，主数字「1」没有视觉重心。
- 两端「我的」标签页：标题叫「设置」，整页是纯列表（吸引力 2/10）。
- 陪跑员汇合页：拿不到方向时仍画一个空的方位圆，占约 1/4 屏，却什么也不指。

## What Changes

- 完成页在绿卡下面加国标星级进度卡（取 `GET /api/volunteer/achievements`，进页面重新拉，含刚跑完的这一单；拉不到就整块不出现）。
  - 「第 N 次一起跑」与「里程 · 用时」**早已实现**（`VolunteerOrderV2.swift` 的 `.completed`），不动。
  - **不加**「本次计入志愿时长」：后端没有按单的服务分钟字段（`OrderModels.swift` 注释），客户端不编。
- 成就页：主数字卡改为主色实心底、白字；已解锁勋章从逐行列表改为圆形徽章一排（与首页「我的徽章」同一组件 `VolunteerBadgeMedallion`，大号实心版）；无障碍字号档退回逐行列表。**不列未解锁勋章**（契约只给已解锁的列表，写死名称是第二个源）。
- 「我的」标签根页标题改为「我的」，顶上加个人卡：跑者「本月跑了 N 次，一共 X 公里」（与记录页同一 view model、同一句文案；只有月度接口）；陪跑员「已完成 N 次陪跑 / 累计服务 X 小时」，整行进服务成就页。从陪跑员首页齿轮（标签叫「设置」）进入的那一页仍叫「设置」、不显示个人卡。
- 汇合页：`relativeDegrees == nil`（太远 / 位置未知 / 拿不到朝向）时不画方位盘，「让手机响起来」上移为第一个动作；有方向后方位盘按原过渡淡入。
- Mock：种成 `COMPLETED` 的订单带 `completedTogetherCount = 3`，让完成页主路径在 Mock 里走得到。

## Non-goals

- 不加排行、不加与他人比较、不加成就弹层（design-direction §1 的三条「不抄」）。
- 不动陪跑员完成页右上角的「求助」（AGENTS §6：负责人 09-26「所有订单页都显示」）与汇合页琥珀头卡（DECISIONS-v2 V13）。
